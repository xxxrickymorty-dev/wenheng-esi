## 1. 主流程（happy path）

```
┌──────────────────────────────────────────────────────────────────┐
│ 文衡 · 工作台                    [报告库] [审核台] [分析台] [台账]   👤 卜彤(admin) │
├──────────────────────────────────────────────────────────────────┤
│  本期 202609 · 第 40 期                        [切换期次 ▾]         │
│                                                                   │
│   ① 取数贴表 ──→ ② 放入输入 ──→ ③ 一键生成                          │
│   ✓ 台账齐         ✓ 已就位        [ 开始生成 ]                     │
│      ↑点击可复查     2.1 MB · 今天 09:14                            │
│                                                                   │
│   预测模型：用推荐（按学科，5 科已指定）  [展开自定义]                  │

├──────────────────────────────────────────────────────────────────┤
│  报告（已生成时显示在这里）                                            │
│   · 未生成 → 空态文案（见 §3）                                        │
│   · 已生成 → 直接嵌对勘本（报告是主角）                                 │
└──────────────────────────────────────────────────────────────────┘
```

**关键设计**：第 ① 步不是「贴完了自己勾」——系统能**检查台账**（流水线断言本来就在做这件事：
「宽表 XX 含期次 202609」）。所以给一个 **[检查台账]**，点一下就说「还缺 3 张表 5 列」。
> ⚠ 需后端支持：只读的台账检查端点（复用断言逻辑，**不落盘**——不能因为检查而把成品撤下）。

## 2. 生成中（点下按钮之后）

五步进度（复用现有 SSE `/api/jobs/{id}/events`，先回放历史再发状态）：

```
生成中 · 已用 8 秒            [看日志] [取消]
 ①解析台账 ✓  ②算大表 ✓  ③预测回测 ✓  ④出图 ⟳ (68/99)  ⑤装配 …
```

- 每一步显示**人话**（不是 `run_parse` / `run_compute`）
- 出图这类长步骤给**计数进度**（68/99），不是转圈
- 页面标题栏与 favicon 同步状态（切到别的标签也知道跑完了）——可选增强

## 3. 状态清单（每个状态：显示什么 / 能做什么）

| 状态 | 界面 | 用户能做 |
|---|---|---|
| 空：本期无输入 | 「本期还没有放入监测表」+ [上传台账]（≤50MB，仅 .xlsx） | 上传 / 换期次 |
| 待生成 | 三步条 + 主按钮 [开始生成] | 检查台账 / 改模型 / 开始 |
| 进行中 | 五步进度 + 计时 | 看日志 / 取消 |
| **成功** | 「✅ 已生成 · 用时 17 秒 · 红色件 704 条 · 99 张图」+ [打开报告] [复核并签单] | 下一步 |
| **失败（解析）** | 「❌ 解析没通过：宽表『学科态势』缺 202609 列」+ 缺什么清单 + [重新生成] | 回 Excel 补 → 重跑 |
| 失败（其他步） | 同上，但说明**成品没被改动**：「上一版报告仍然有效」 | 重跑 / 看日志 |
| 中断（retrying / stalled） | 「第 2 次重试中…」「看起来卡住了（已 3 分钟无输出）」+ [取消] [看日志] | 取消 / 等 |
| 已签发 | 朱印 + 签发人/时间；重新生成会**使签名失效**（金印） | 重签 / 撤回 |

## 4. 错误态文案（逐条，都要能回答"哪里错了 + 下一步做什么"）

| 情况 | 文案 |
|---|---|
| 缺列/缺数 | 「台账里《千分之一被引阈值》还没有 202609 列 → 补上这一列，回来点『重新生成』」 |
| 台账格式变了 | 「解析器不认识这张表（新增了工作表或改了表头）→ 把台账发给开发适配，其余步骤不受影响」 |
| 台账被改过（运行期 sha256 护栏） | 「检测到台账在运行中被修改，已拦停 → 确认没有别的程序在改它，然后重跑」 |
| 断言 FAIL 但已生成一半 | 「本次没有出稿，**上一版报告仍然有效**（已隔离到 `_superseded`，可追溯）」 |
| 服务没起来 / 断网 | 「连不上服务 → 检查本机服务是否在跑；你的台账与上一版报告都没有受影响」 |

## 5. 预测模型选择（rick 2026-09-22 定：**按学科选，默认推荐**）

**第一层只问一句话**：「预测模型：**用推荐** / 我自己指定」——不打断三步动线。

展开后是一张表（默认值＝`esi_v1` 的按学科推荐）：

| 学科 | 推荐 | 我的选择 |
|---|---|---|
| 化学 | 季节性ETS模型 | [季节性ETS模型 ▾] |
| 工程学 | SARIMA模型 | [SARIMA模型 ▾] |
| …（22 学科） | | |

**每个模型边上给简介**（初稿，**需模型作者 quxiaoming313 核对**）：

| 模型 | 简介（供馆员选） |
|---|---|
| Holt趋势模型 | 只抓长期趋势、不管季节。适合稳定上升/下降的学科，外推最直接。 |
| 阻尼Holt模型 | 趋势会「减速」——越往前推越保守。适合增长在放缓的学科。 |
| 季节性ETS模型 | 抓「6 期一轮」的双月节律。适合受学年/发布节奏影响的指标。 |
| SARIMA模型 | 趋势 + 季节都管，参数在最初 30 期按 AIC 选定后固定。通用、稳。 |
| 经验贝叶斯状态空间模型 | 把趋势与季节当「状态」逐期更新。对噪声大的序列更稳健。 |

**两条路线必须说清**：被引（citation）与排名（rank）**一致率只有 2/8**——界面上要写
「本次预测的是哪条路线」，不能让人以为是一个结论。
**报告侧**：选择写入 `out/<期次>/forecast_choice.json`；报告的预测章用所选模型出图，
并附**对应解读**（确定性句骨架；要润色则过 `flexible/polish.py` 的数字防护盾）。
