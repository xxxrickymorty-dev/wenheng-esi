# UX 第一性原则 · 用户与任务

> rick 定调（2026-09-22）：**工作区的设计要从用户思维出发，一切以用户体验为第一性原则。**
> 本文件是这条原则的落地：用户是谁、他们现在怎么做、痛点在哪、每个工作区开工前必须回答的四问。
> **任何工作区动工前先读这里。设计与它冲突时，以用户任务为准——不是以后端能力为准。**

## 一、用户是谁（按优先级）

| 用户 | 场景 | 现在怎么做 | 痛点 |
|---|---|---|---|
| **馆员（admin，主用户）** | 每期出报告：取数 → 贴台账 → 跑流水线 → 复核 → 补人工项 → 签单 | 双击 `一键出报告.bat`；在 Word 里**搜索** `【手工：` 逐项补；红色件清单是 `.md` 文件 | ① 贴表纯手工，错了才知道；② 人工项散在 docx 里、靠搜索找；③ 复核没有顺手的逐格对照工具；④ 出错只看到断言文本，不知道"下一步做什么" |
| **guest（普通只读用户；学科馆员/馆领导的只读访问也属于 guest）** | 浏览报告安全预览 | 登录后进入阅览室 guest 预览 | 只能看封面、目录和名词解释；不能访问全文、DOCX、数值页、图或附件 |
| **评委（观众，不是产品角色）** | 10 月底线上演示 + 11 月现场答辩 | 看系统演示与 guest 安全预览 | 要在几分钟内看懂「这东西解决了什么」；guest 权限边界不变 |

**权限模型（rick 2026-09-22 定；guest 范围按 2026-09-25 裁定补充）**：一个馆员（卜彤），**暂无并发**；角色仍为 admin 与 guest 两级。
**admin 可编辑修改**（含在线审核与回写）；guest 只可安全预览封面、目录、名词解释，不可访问任何期次的全文、DOCX、数值页、图或附件，签单状态不构成例外。
权限分级同时是评分表里「数据安全」那一项的直接抓手。

## 二、真实任务清单（来源：`../docs/操作手册（馆员版）.md`）

每期三步（约 5 分钟人工 + 17 秒机器）：

1. **取数贴表**：ESI 官网 / InCites → 台账 xlsx，**按列追加**（不覆盖历史）
2. **放入输入目录**：`input/<期次>/监测表.xlsx`
3. **双击一键出报告** → 全绿＝数据完整；FAIL＝写明缺哪张表哪一列，补上重跑

产出之后**仍需人工**：`【手工：…】` 6 类（ESI 发布日期 / 当期全球机构总数 / 去年同期升幅% /
学院贡献度 / 省级高校总数 / 目录页码）+ 省表非云大高校数据 + 顶尖论文清单。

**已有的在线化基础**（旧站，2026-09-19）：`/p/<期次>/fill`（在线填 `manual_inputs.json`）、
`/flag`（存疑 `review.json`）——新工作区要接着这两条往下做，不另起一套。

## 三、每个工作区开工前的四问（缺一不许动工）

1. **谁**在什么**场景**下用它？（办公室 / 演示现场 / 手机？）
2. 他**现在**怎么完成这件事？哪一步最烦？
3. 用完之后**什么变了**？（他少做了什么、快了多久）
4. **怎么知道做对了**？——判据要一句话说清，且**是他能验证的**，不是"测试通过"

## 四、体验判据（验收时逐条问）

- 第一屏能不能回答「我现在该做什么」？
- 出错时，他看到的是「哪里错了 + 下一步做什么」，还是错误码？
- 有没有明确的「完成」信号（而不是"看起来跑完了"）？
- 关掉页面 / 换设备，状态还在吗？
- 键盘可达、窄屏可用、断网有交代？
- 界面文案与代码注释**不出现技术术语**（`run_parse` / 断言 / sha256 一律翻译成人话）——
  馆员不懂代码；交付纪律见 `AGENTS.md`「两条交付纪律」。

## 七、第一屏的第一性原理（从评分标准推，不是从页面结构推）

**评分标准里的事实**（`../评审文档/16-赛前培训资料分析与得分作战清单（2026-09-19）.md`）：

- 阶段一 = 网络评审 40% + **线上汇报 60%**；阶段二 = 阶段一 40% + **现场答辩 60%** → **分在演示里**
- 10 分钟结构：1 分痛点 → 1 分原流程为什么不行 → 2 分系统与 Agent 设计 → **3 分「真实任务 Demo：
  原始数据 → 24 秒 → 可签发的 Word 报告」** → 2 分效果数据 → 1 分创新与推广
- 金句：**「Show the Task, Not the Menu」**——让评委看到**任务被完成**，而不是菜单被点击
- 最弱维度：**展示与推广**（可复用 / 运维 / 安全与权限分级）；最强维度：实施与效果（弹药没上膛）

**推论：第一屏 = 「这一期现在到哪一步、下一步做什么」——任务视图，不是工作区菜单。**

| 角色 | 第一屏 |
|---|---|
| **admin（馆员）** | 本期任务条：`①取数贴表 → ②放入输入 → ③一键生成`，当前卡在哪一步、主按钮是什么、上一期签发状态 |
| **guest（普通只读用户）** | guest 安全预览入口，只显示封面、目录、名词解释；不显示全文、DOCX、数值页、图或附件 |
| **报告已生成时** | admin 仍按现有复核/签发工作流进入报告；guest 仍只看上述安全预览，签单状态不开放全文、DOCX、数值页、图或附件 |

**明确不做**：五个工作区的九宫格/卡片墙——那正是评委说的 "Menu"。
工作区切换是次要导航（顶栏）；admin 的主角是「本期任务」，guest 的报告入口只展示安全预览。

## 八、预测模型选择（rick 2026-09-22 补充的需求）

**馆员要什么**：在线选择预测模型；**每个模型边上给简介**帮助她选；
**报告里、在她所选模型那一块，生成该预测的解读**。

**现状与缺口**：

| 项 | 现状 | 缺口 |
|---|---|---|
| 模型清单 | `src/esi_v1/MODEL_MANIFEST_V1.json`：Holt趋势 / 阻尼Holt / 季节性ETS / SARIMA / 经验贝叶斯状态空间（5 个） | — |
| 选择入口 | 旧站 `/forecast` 页有下拉（recommended / all / 5 个模型名） | **只有名字、没有简介**；且是**研究工具** |
| 与报告的关系 | ❌ 选谁都不影响报告；报告的预测章是生产线（方法 B + 母版继承的 4 张原生图） | **要打通**：选择 → 报告预测章用该模型 → 附对应解读 |
| 两条路线别混 | `task` = `citation`（被引）/ `rank`（排名），**两维度结论一致率仅 2/8**，任一维度不能单独当学科结论 | 选择界面要说清"你在选哪条路线" |

**落法（待确认）**：选择写进本期运行参数（如 `out/<期次>/forecast_choice.json`）；
解读文字走**确定性句骨架**（不是让模型编数字——铁律 7a 不变；要润色则过 `flexible/polish.py` 的数字防护盾）。

## 九、视觉基线（2026-09-22 立，配色待 rick 定稿）

| 项 | 规则 | 为什么 |
|---|---|---|
| **图标** | **一套内联 SVG**（24 视框 / 1.7 描边 / 圆头），不用图标字体、不引 CDN | 统一观感；断网可用；`<use>` 引用，改一处全局一致 |
| **字号** | 正文 **17px** 起，最小标签 **13.5px**，主按钮 18px、点击区 ≥44px | 馆员与评委**年龄偏大** |
| **对比度** | 所有「文字/底色」组合**实测 ≥4.5:1**（WCAG AA），不靠目测 | 同上；已用脚本逐对验过 |
| **状态表达** | 颜色 **+ 图标 + 文字** 三重编码（失败不能只靠红色） | 色觉差异 + 投影偏色 |
| **配色** | 三套可切换：朱批原色系 / 莫兰迪 / **莫兰迪 + 朱砂点睛**；纯莫兰迪原版实测 6 处不达 AA，已按实测调深 | 见 `mockups/生成台.html` 右上角切换 |
| **朱砂的用法** | 只标「签章 / 需要人拍板 / 主按钮」，**不作装饰色** | 沿用演示站既有铁律 |
