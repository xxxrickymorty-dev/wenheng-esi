# UX 第一性原则 · 用户与任务

> rick 定调（2026-09-22）：**工作区的设计要从用户思维出发，一切以用户体验为第一性原则。**
> 本文件是这条原则的落地：用户是谁、他们现在怎么做、痛点在哪、每个工作区开工前必须回答的四问。
> **任何工作区动工前先读这里。设计与它冲突时，以用户任务为准——不是以后端能力为准。**

## 一、用户是谁（按优先级）

| 用户 | 场景 | 现在怎么做 | 痛点 |
|---|---|---|---|
| **馆员（admin，主用户）** | 每期出报告：取数 → 贴台账 → 跑流水线 → 复核 → 补人工项 → 签单 | 双击 `一键出报告.bat`；在 Word 里**搜索** `【手工：` 逐项补；红色件清单是 `.md` 文件 | ① 贴表纯手工，错了才知道；② 人工项散在 docx 里、靠搜索找；③ 复核没有顺手的逐格对照工具；④ 出错只看到断言文本，不知道"下一步做什么" |
| **guest（普通只读用户；学科馆员/馆领导的只读访问也属于 guest）** | 浏览报告安全预览 | 登录后进入阅览室 guest 预览 | 只能看封面、目录和名词解释；不能访问全文、DOCX、数值页、图或附件 |
| **评委（观众，不是产品角色）** | 10 月底线上演示 + 11 月现场答辩 | 看系统演示与 guest 安全预览 | 要在几分钟内看懂「这东西解决了什么」；guest 权限边界不变 |

**权限模型（rick 2026-09-22 定；guest 范围按 2026-09-25 裁定补充）**：一个馆员（卜彤），**暂无并发**；角色仍为 admin 与 guest 两级。
**admin 可编辑修改**（含在线审核与回写）；guest 只可安全预览封面、目录、名词解释，不可访问任何期次的全文、DOCX、数值页、图或附件，签单状态不构成例外。
权限分级同时是评分表里「数据安全」那一项的直接抓手。

> **2026-10-11 修订（rick 测试反馈定案）**：guest 取消，改两级 **admin（管理员）／operator（操作员，账号 `demo`，评委用）**。
> 操作员**进工作区**，但取数台 / 台账 / 运行档案 / 红件清单 / 逐格溯源不可见；**所有写动作（跑生成、重跑、上传、签单、撤回、回滚、
> 保存预测选择、在线填、生成灵活报告、切 AI 开关）由服务端拦住（只读）**。陈列馆两种角色同看全内容
> （封面 / 目录 / 名词解释 + 报告正文 + 数字体检 / 指标 / 大表 / 顶尖论文 / 预测）。
> 上文表格与「权限模型」段中的 guest 表述以本条为准；spec：`docs/specs/2026-10-11-角色分级与陈列馆正文.md`。

## 二、真实任务清单（来源：`../docs/操作手册（馆员版）.md`）

每期三步（约 5 分钟人工 + 17 秒机器）：

1. **取数**：取数台一键导出、逐份核验 → 自动建本期监测表 → 馆员核对 → **并入台账**（只动当期列；ADR-0004）
2. **放入输入目录**：`input/云大全学科排名、阈值动态检测表.xlsx`（母本，`input/` 只放它）
3. **双击一键出报告** → 全绿＝数据完整；FAIL＝写明缺哪张表哪一列，补上重跑

产出之后**仍需人工**：`【手工：…】` 6 类（ESI 发布日期 / 当期全球机构总数 / 去年同期升幅% /
学院贡献度 / 省级高校总数 / 目录页码）+ 省表非云大高校数据 + 顶尖论文清单。

**已有的在线化基础**（旧站，2026-09-19）：`/p/<期次>/fill`（在线填 `manual_inputs.json`）、
`/flag`（存疑标记，2026-10-21 起存进状态库）——新工作区要接着这两条往下做，不另起一套。

## 三、每个工作区开工前的四问（缺一不许动工）

1. **谁**在什么**场景**下用它？（办公室 / 演示现场 / 手机？）
2. 他**现在**怎么完成这件事？哪一步最烦？
3. 用完之后**什么变了**？（他少做了什么、快了多久）
4. **怎么知道做对了**？——判据要一句话说清，且**是他能验证的**，不是"测试通过"

## 四、体验判据（验收时逐条问）

- 第一屏能不能回答「我现在该做什么」？
- 出错时，他看到的是「哪里错了 + 下一步做什么」，还是错误码？
- 有没有明确的「完成」信号（而不是"看起来跑完了"）？
- 关掉页面 / 换设备，状态还在吗？
- 键盘可达、窄屏可用、断网有交代？
- 界面文案与代码注释**不出现技术术语**（`run_parse` / 断言 / sha256 一律翻译成人话）——
  馆员不懂代码；交付纪律见 `AGENTS.md`「两条交付纪律」。

## 七、第一屏的第一性原理（从评分标准推，不是从页面结构推）

**评分标准里的事实**（`../评审文档/历史/16-赛前培训资料分析与得分作战清单（2026-09-19）.md`）：

- 阶段一 = 网络评审 40% + **线上汇报 60%**；阶段二 = 阶段一 40% + **现场答辩 60%** → **分在演示里**
- 10 分钟结构：1 分痛点 → 1 分原流程为什么不行 → 2 分系统与 Agent 设计 → **3 分「真实任务 Demo：
  原始数据 → 24 秒 → 可签发的 Word 报告」** → 2 分效果数据 → 1 分创新与推广
- 金句：**「Show the Task, Not the Menu」**——让评委看到**任务被完成**，而不是菜单被点击
- 最弱维度：**展示与推广**（可复用 / 运维 / 安全与权限分级）；最强维度：实施与效果（弹药没上膛）

**推论：第一屏 = 「这一期现在到哪一步、下一步做什么」——任务视图，不是工作区菜单。**

| 角色 | 第一屏 |
|---|---|
| **admin（馆员）** | 本期任务条：`①取数 → ②核对并并入 → ③一键生成`，当前卡在哪一步、主按钮是什么、上一期签发状态 |
| **guest（普通只读用户）** | guest 安全预览入口，只显示封面、目录、名词解释；不显示全文、DOCX、数值页、图或附件 |
| **报告已生成时** | admin 仍按现有复核/签发工作流进入报告；guest 仍只看上述安全预览，签单状态不开放全文、DOCX、数值页、图或附件 |

**明确不做**：五个工作区的九宫格/卡片墙——那正是评委说的 "Menu"。
工作区切换是次要导航（顶栏）；admin 的主角是「本期任务」，guest 的报告入口只展示安全预览。

## 八、预测模型选择（rick 2026-09-22 补充的需求）

**馆员要什么**：在线选择预测模型；**每个模型边上给简介**帮助她选；
**报告里、在她所选模型那一块，生成该预测的解读**。

**现状与缺口**：

| 项 | 现状 | 缺口 |
|---|---|---|
| 模型清单 | `src/esi_v1/MODEL_MANIFEST_V1.json`：Holt趋势 / 阻尼Holt / 季节性ETS / SARIMA / 经验贝叶斯状态空间（5 个） | — |
| 选择入口 | 旧站 `/forecast` 页有下拉（recommended / all / 5 个模型名） | **只有名字、没有简介**；且是**研究工具** |
| 与报告的关系 | ❌ 选谁都不影响报告；报告的预测章是生产线（方法 B + 母版继承的 4 张原生图） | **要打通**：选择 → 报告预测章用该模型 → 附对应解读 |
| 两条路线别混 | `task` = `citation`（被引）/ `rank`（排名），**两维度结论一致率仅 2/8**，任一维度不能单独当学科结论 | 选择界面要说清"你在选哪条路线" |

**落法（待确认）**：选择写进本期运行参数（如 `out/<期次>/forecast_choice.json`）；
解读文字走**确定性句骨架**（不是让模型编数字——铁律 7a 不变；要润色则过 `flexible/polish.py` 的数字防护盾）。

### 陈列馆豁免（rick 2026-10-26 裁「按推荐优化」）

陈列馆（`web/src/library/`，`/app/shelf/`）是**展陈面**，不是操作面：木色书架 + 金线 + 衬线是它被记住的钩子，
不该被工作台的六档音阶碾平。故对 §九 作**登记式豁免**——豁免的是「值」，不是「底线」。

| 项 | 处置 | 为什么 |
|---|---|---|
| 字号 | **不进六档音阶**。沿用静态稿自有序列（2026-10-26 实测 16 档，11–46px，含 clamp 英雄题），但**正文级文字下限 11px** | 展陈面需要英雄题 / 图注 / 铭牌多层尺寸；工作台是操作面，需要压平 |
| 配色 | **第三套色板**：木 `#191310` / 金 `#C9A961` / 纸 `#F4F1E8` 三族，登记在 `src/index.css` 的 `--lib-*` 段，**不参与蓝绿主题切换** | 「馆」不该因为切主题变成蓝书架 |
| 图标 | 无图标集（品牌标记是内联 SVG） | — |
| **对比度** | **不豁免**。工作区标准原样适用：逐格实测 ≥4.5:1（2026-10-26 验 11 处，5 个视口） | 评委会场投影偏色，这条不是审美 |
| **零圆角** | **不豁免**。加载 / 错态卡与未登录闸页一律 0 圆角（2026-10-26 把 `gate.html` 的 14px 改回 0） | 同一个概念不能两种形状 |
| **44px 点击区** | **部分豁免**：独立按钮达标（提交 48px / 再试 44px）；**正文内联链接**（试问 chip、页脚、正文链接）与**全景工具条**按 WCAG 2.5.8 例外处理，下限 24×24（实测最小 25px） | inline 链接与密集排列的画布控件不适合 44px；但独立按钮没有理由不达标 |

## 十、信息减负与通用规范（rick 2026-09-28 定）

**硬指标（新页面/改稿先自检，样板见 `web/mockups/生成台-信息减负对照稿.html`）**
- 单条小字（hint）≤ **24 字**；页首导语 ≤ **60 字**（≤2 行）；
- 首屏（≈860px 视口）可见文字 ≤ **180 字**；每屏主动作 ≤ **1 个**；
- 口径/边界/免责声明**全站只有一份**（顶栏「ⓘ 说明」——2026-10-24 起页脚撤销，收进顶栏），页面内不再各自复读。

**信息分三档**
- 常驻首屏：①「我现在该做什么」②错误/告警（缺什么＋下一步）③关键状态（期次、签单状态）；
- 收起（就地折叠 ▸）：口径与边界、来源说明、操作提示、明细表；
- 只留一处：跨页重复的同一句话（只读声明、数字来源声明等）。

**空态 / 错态模板**
- 空态 = 一句话 + 一个下一步动作（给按钮或链接）；**禁止"只有解释没有动作"**；
- 错态 = 缺什么 + 怎么补 + 一个**有效**的重试（403/404 不再显示无效"再试一次"）。
- **环境故障**（如本机数据存储只能只读）＝页首一条**常驻横幅**（复用 `.banner.warn`，不用会自己消失的提示）：
  说清哪些还能用、哪些动作会失败、东西没丢；不弹窗、不给"再试一次"，也不遮住下面的操作用。

**危险动作**
- 破坏性动作（撤回签单、重跑、重出、上传覆盖、放弃修改）**先确认**，写明后果；
  确认样式＝**行内二次确认**（按钮原地变「确认重跑？」，3 秒后退回），不做弹窗；
- 「重跑 / 重出」在案发现场给**「回滚到上一版」**（旧稿在 `_superseded/`）；
  入口两处：重跑按钮旁 ＋ 运行档案。

**术语与文案**
- 界面文案一律用 `GLOSSARY.md` 的词；禁用词按黑名单执行（单源 `web/src/lib/banned.ts`，自动检查进 `tools/check_web_app.py`）。
- **统一词表（2026-10-17 冗余收敛对照稿①过审；全站只用表内词，不再各自起名）**：
  - 每期第 1 步：机器进度叫「取数」，人的步骤叫「取数核验」（屏题＝步骤名；口语地点叫「取数台」）；
  - 出稿：机器叫「一键生成」，人的步骤叫「生成初稿」；取数一步的机器动作一律叫「取数」，按钮不写「下载」（「下载数据专用浏览器」为既有名词，豁免）；

## 十一、请求竞态与期次隔离规范（2026-10-25 探针后定）

**问题域**：用户快速切期次时，先发后至的响应不许盖掉晚发先至的——报告页数字串期是
**数据正确性事故**，不是体验问题。防它靠两个机制，各管一件事：
**按期自增序号**管「同期重发」（同一期连点两次，迟到的旧响应作废）；
**按 key 分桶**管「跨期串写」（切走的期次数据留着，切回来不用重取；旧响应只写进自己那一桶，盖不到新期次）。

**现状盘点（2026-10-25 审核实测；四种写法都正确，问题只在不统一）**

| 写法 | 站点（现行行号） | 机制 |
|---|---|---|
| ① 按期 ref 计数器 | `App.tsx:95`（全局计数器，管列表）· `App.tsx:117`/`129`（`usePeriodResource` 两实例） | 序号＋分桶都在 hook 里 |
| ② alive 清理标志 | 按期次：`Report.tsx:88`/`148`/`343`、`Tools.tsx:65`/`78`；全局卸载：`App.tsx:248`/`293` | effect 卸载置亡旗，防卸载后 setState |
| ③ 状态带 key 标签 | `Report.tsx:103`、`Tools.tsx:53` | 渲染前比对 key，不一致整块不渲染 |
| ④ 任务维度双守卫 | `hooks/useJobRun.ts:63`/`71` | snapshotRequestRef ＋ isCurrent(jobId, generation) |

**新代码一刀切（不许起第五种）**
- 取「按期次的一份数据」→ 一律 `usePeriodResource`（commit `8e406444` 引入，见 `web/src/hooks/usePeriodResource.ts`）：
  调用方只写 load / onData / onError 三件事；options 必须 `useMemo(..., [])` 包住——request 的身份稳定性是
  消费方依赖数组（如 `onRunTerminal`）的前提。只作废在途、不重发 → 用它的 `invalidate`。
- 一次性、无 key 的取数（全局列表、探活）→ 全局计数器＋卸载作废（参照 `refreshPeriods`），不为它扩 hook。
- 任务 / 作业维度 → 留在 `useJobRun` 的双守卫里，不混进期次 hook。

**存量处置**
- ②③ 是对的，**不主动重写**（赛前尤其——重写只会引入新 bug）；
- 新页面 / 新资源不许再手写新 idiom；改到旧站点就顺带对齐到本规范，并在提交信息里写明对齐了哪处。

**验收一句话**：任何「按期次取数」的代码，说得出它靠哪个机制防串号；说不上来的不许合。
