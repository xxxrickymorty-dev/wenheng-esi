# 取数台 · 接线清单（X1 修订版 · 2026-09-29 决策）

> 配套静态稿：`web/mockups/取数台.html`（单文件、双击即开；六场景可切）
> 依据：wayfinder 票 12/13、`dev/PLAN.md` X 线、rick 2026-09-29 决策（建副本先行 → 馆员核对 → 并入主台账）
> 边界（全局红线）：登录在取数专用浏览器内完成（**会话过期由取数脚本自动重登**——2026-10-14 起）、账号不落盘于本系统；页面只显示状态、只发起**人按的动作**；
> 没有模型触发路径；数字全部来自后端，前端不换算、不聚合。

## 0. 数据流（202611 例 · 本清单的一切以此为准）

```
① 取数：下载 → 逐文件核验（通过才计入）                      【人按一键】
② 自动清洗 --out → 新建 input/202611/监测表.xlsx            【自动，随①完成】
   只写 202611 列；主台账不碰；历史列一字不动
③ 馆员核对「本期新增列核对表」（页面）或直接打开监测表文件    【人】
④ 录入核对通过 → 把 202611 列并入主台账                       【人按确认】
   写前备份 · 冲突拒写 · 列白名单 · 旧列逐格比对 · 写后 audit
⑤ 生成台一键生成（用已核对快照做开跑输入）                    【人按】
```

口径句：**「下载完成 ≠ 台账已更新：先核对本期监测表，核对通过才并入。」**

现状对照（为什么要改）：
- 现行主路径是反的——先写（贴）主台账、再另存副本，且没有审核闸；清洗链 `clean_ledger.py --write` 同样是先写主台账。
- 「先副本后主台账」直接复用现成模式：清洗链本来就有 `--out`（只写副本）/ `--write`（写主台账）两档。
- 机械保证三项是新增：列白名单、旧列逐格比对、写后审计接线（`src/ledger_patch.py` 的 `audit()` 已存在但没被调用）。

## 2. 新接口（后端配套；形状先入契约文档，再动前端）

| 方法 | 路径 | 用途 | 说明 |
|---|---|---|---|
| GET | `/api/periods/{period}/acquisition` | 取数状态：preflight、9 组与逐文件核验、数据期、副本状态（未建/待核对/已并入）、并入时刻 | admin、只读 |
| GET | `/api/periods/{period}/acquisition/review` | 「本期新增列核对表」：按工作表列出将并入的列、内容与来源 | admin、只读；懒加载 |
| POST | `/api/periods/{period}/acquisition/retry` | 断组重试（body：组 id） | admin、人按键 |
| POST | `/api/periods/{period}/acquisition/merge` | 并入主台账（核对通过后的确认） | admin、人按键；写路径见 §5 |

响应形状建议（照静态稿字段；文件名里的数字随当期篇数变，前端**原样显示、不解析**）：

## 5. X3 实现记录（2026-09-29 下午落地 · `tools/acquire.py`）

已实现的五个子命令（全部人触发；写成状态、读在取数台）：

| 子命令 | 做什么 | 落点 |
|---|---|---|
| `scan <期次>` | 两路下载包**逐文件核验**（能读 + 表头指纹 + 行数下限）→ 写状态 | `src/acquisition_state.py` |
| `copy <期次>` | 清洗链 `--out` 新建 `input/<期次>/监测表.xlsx`（**主台账不碰**，构建前后校验母版 sha） | 复用 `tools/clean_ledger.py` |
| `merge <期次>` | 守卫（母版 sha == 建副本时的底座）→ `clean_ledger --write` 并入 → **写后五查** | `src/ledger_merge.py` + `tools/acquire.py` |
| `preflight <期次>` | CDP 连通 + ESI/InCites 登录探测（需系统 python 的 playwright） | `_PROBE` 片段 |
| `fetch <期次>` | 按 9 组跑 `clarivate_*_fetch.py` → 每组后自动 scan → 全过自动 copy | 断组重试 = `--groups <id>` |

**并入的设计修正（重要）**：原计划「把副本字节搬进母版」。探针（对着 202607 副本 vs 现母版）显示两者之间夹着
styles / sharedStrings / calcChain / charts / 结构成员等大量**合法**字节变化——逐字节白名单既挡不住也证不了。
改成：**落笔 = 清洗链自己的 `--write`（确定性同值、每工具自带冲突拒写+备份），写后用副本逐格核对**——
「审的＝写的」从机制改成**可验证属性**（五查：没删 / 旧格不动 / 新增归期 / 审写同值 / XML 良构；
不过就不宣告成功、备份可回退）。实现见 `src/ledger_merge.py`，单测 `tests/test_ledger_merge.py` 7 例。

**实测发现（值得记）**：
- 对**已并入过的历史期次**重建副本会撞「冲突拒写」实锤：202609 存档重算「国内高校数」=128，台账里是 129；
  202605 快照缺「云南大学研究领域」并另有 4 处冲突——**建副本只对未并入的当期有意义**，历史期次一律拒绝重算（设计如此）。
- `scan` 对历史期次如实标注 `copy.state='merged'（报告已出，视同已并入）`，不假装有核对流程。
- 状态目录支持 `WENHENG_ACQ_STATE_DIR` 覆盖（集成测试/演练不碰真状态）。

**半实弹**（2026-10-14 更新）：登录条件已实弹验证——两个取数脚本内置自动重登（Chrome 自动填表 + 点 Sign in；ESI / InCites 过期均自动恢复、幂等）；**9 组下载待首次真跑**（202611 发布时）；其余链路（scan/copy/merge/接口/UI）已实测。
