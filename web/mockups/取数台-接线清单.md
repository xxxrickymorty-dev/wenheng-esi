## 2. 新接口（后端配套；形状先入契约文档，再动前端）

| 方法 | 路径 | 用途 | 说明 |
|---|---|---|---|
| GET | `/api/periods/{period}/acquisition` | 读取数状态（整体＋9 组＋逐文件核验＋开始前检查＋数据期＋入库状态） | admin、只读 |
| POST | `/api/periods/{period}/acquisition/retry` | 断组重试（body：组 id） | admin、人按键；执行载体见 §5 |
| POST | `/api/periods/{period}/acquisition/accept` | 验收入库 | admin、人按键；写路径由后端做 |

响应形状建议（照静态稿字段；文件名里的数字随当期篇数变，前端**原样显示、不解析**）：

```
{
  "period": "202609",
  "data_period": { "esi": "2026-09", "incites": "2026-08-31" },
  "library": { "in_library": false, "at": null },
  "preflight": { "browser": "ok", "esi": "ok", "incites": "ok" },   // ok / bad / waiting
  "totals": { "groups": 9, "expected": 64, "verified": 31, "downloaded": 32, "failed": 0 },
  "groups": [
    { "id": "esi-papers", "source": "esi", "index": 4, "title": "云大论文清单",
      "state": "live", "verified": 5, "downloaded": 6,
      "files": [ { "name": "1234top.xlsx", "label": "Top 论文 · Excel", "state": "ok" } ] }
  ]
}
```

组状态与文件状态的取值以静态稿为准：组 `pending / live / done / fail / retrying`；文件 `pending / received / ok / bad`。

## 3. wb.ts 与任务链联动（票 12 的「状态面」）

- `web/src/api.ts` 的 `PeriodDetail` 扩展可选字段（缺省时显示「未就绪」，沿现有诚实态）：
  `acquisition?: { in_library: boolean; verified: number; total: number; failed: number }`
- `web/src/wb.ts` 的三步条第一步「取数贴表」：
  - 台账已齐 → 维持「台账已齐」；
  - 未入库 → 「数据还没取齐」/「取数中（31 / 64）」；
  - 已入库未贴表 → 「数据已入库 · 待贴表」。
  - 口径只此一处：取数状态只来自新接口，不另建第二套判断。
- 生成台期次卡（`Workbench.tsx`）：状态带加「数据齐否」指示（如 `已入库 64 / 64` / `数据还没齐`），点击进取数台。
- 三步条本身不改结构，只加第一步的进入链接。

## 4. 运行档案（留痕）

  组清单 / 产物清单 / 核验结果 / 重试次数 / 入库时刻。字段口径对齐票 03（运行档案留痕稿）。

## 5. 与 X3（取数工具化）的接缝

- 本稿只定**界面边界**：页面不跑脚本、不碰浏览器；「开始 / 重试 / 入库」是人触发动作。
- 执行载体（馆员机上的取数脚本）与状态回填方式由票 13 设计定稿后接线；诊断参谋可建议取数（只读判定），执行权在人（R-1）。
