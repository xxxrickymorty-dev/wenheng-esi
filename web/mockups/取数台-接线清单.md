# 取数台 · 接线清单（X1 修订版 · 2026-09-29 决策）

> 配套静态稿：`web/mockups/取数台.html`（单文件、双击即开；六场景可切）
> 依据：wayfinder 票 12/13、`dev/PLAN.md` X 线、rick 2026-09-29 决策（建副本先行 → 馆员核对 → 并入主台账）
> 边界（全局红线）：登录由馆员在取数专用浏览器完成、账号不落盘；页面只显示状态、只发起**人按的动作**；
> 没有模型触发路径；数字全部来自后端，前端不换算、不聚合。

## 0. 数据流（202611 例 · 本清单的一切以此为准）

```
① 取数：下载 → 逐文件核验（通过才计入）                      【人按一键】
② 自动清洗 --out → 新建 input/202611/监测表.xlsx            【自动，随①完成】
   只写 202611 列；主台账不碰；历史列一字不动
③ 馆员核对「本期新增列核对表」（页面）或直接打开监测表文件    【人】
④ 录入核对通过 → 把 202611 列并入主台账                       【人按确认】
   写前备份 · 冲突拒写 · 列白名单 · 旧列逐格比对 · 写后 audit
⑤ 生成台一键生成（用已核对快照做开跑输入）                    【人按】
```

口径句：**「下载完成 ≠ 台账已更新：先核对本期监测表，核对通过才并入。」**

现状对照（为什么要改）：
- 现行主路径是反的——先写（贴）主台账、再另存副本，且没有审核闸；清洗链 `clean_ledger.py --write` 同样是先写主台账。
- 「先副本后主台账」直接复用现成模式：清洗链本来就有 `--out`（只写副本）/ `--write`（写主台账）两档。
- 机械保证三项是新增：列白名单、旧列逐格比对、写后审计接线（`src/ledger_patch.py` 的 `audit()` 已存在但没被调用）。

## 2. 新接口（后端配套；形状先入契约文档，再动前端）

| 方法 | 路径 | 用途 | 说明 |
|---|---|---|---|
| GET | `/api/periods/{period}/acquisition` | 取数状态：preflight、9 组与逐文件核验、数据期、副本状态（未建/待核对/已并入）、并入时刻 | admin、只读 |
| GET | `/api/periods/{period}/acquisition/review` | 「本期新增列核对表」：按工作表列出将并入的列、内容与来源 | admin、只读；懒加载 |
| POST | `/api/periods/{period}/acquisition/retry` | 断组重试（body：组 id） | admin、人按键 |
| POST | `/api/periods/{period}/acquisition/merge` | 并入主台账（核对通过后的确认） | admin、人按键；写路径见 §5 |

响应形状建议（照静态稿字段；文件名里的数字随当期篇数变，前端**原样显示、不解析**）：

```
{
  "period": "202611",
  "data_period": { "esi": "2026-11", "incites": "2026-10-31" },
  "preflight": { "browser": "ok", "esi": "ok", "incites": "ok" },   // ok / bad / waiting
  "totals": { "groups": 9, "expected": 64, "verified": 64, "downloaded": 64, "failed": 0 },
  "copy": { "state": "review", "path": "input/202611/监测表.xlsx" },  // none / review / merged
  "merged_at": null,
  "groups": [
    { "id": "esi-papers", "source": "esi", "index": 4, "title": "云大论文清单",
      "state": "done", "verified": 6, "downloaded": 6,
      "files": [ { "name": "1234top.xlsx", "label": "Top 论文 · Excel", "state": "ok" } ] }
  ]
}
```

组状态与文件状态的取值以静态稿为准：组 `pending / live / done / fail / retrying`；文件 `pending / received / ok / bad`。
核对表形状：`{ sheets: [ { name:"总被引", added:"202611 列", content:"22 个学科各一格", source:"ESI" } ] }`。

## 5. X3（取数工具化）要落的四件

1. **建副本**：清洗链加一路 `--out input/<期次>/监测表.xlsx`（沿用现有 `--out` 模式；从主台账快照 + 当期来源生成）。
2. **并入（新小工具或子命令）**：以**已核对副本**为准，把当期列并入主台账——审的＝写的；
   写前 `ledger_patch.backup()`；冲突拒写（占位空列可直接填，已有不同值即拒，人裁决「以本期为准覆盖」需二次确认）；
   **列白名单**：只允许写当期列；**旧列逐格比对**：写前记录、写后必须一字不变；写后接 `ledger_patch.audit()` 四查。
   任一项不过 → 停 + 待人工，不给「静默继续」。
3. **触发与执行**：人触发、馆员机执行、人工登录确认（票 13 原定调不变）；页面发起、状态回填。
4. **覆盖审计**（rick 09-29 定）：逐列核对「清洗链实际覆盖 vs 给馆员的 v3 承诺 vs 台账全部当期列」，出差距表；
   界面与材料只承诺审到的列，覆盖不到的标「需人补」。
- AI 位置：诊断参谋可建议取数（只读判定），执行权在人；模型永不触发（R-1 不变）。
