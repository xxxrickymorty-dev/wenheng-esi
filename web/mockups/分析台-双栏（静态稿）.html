本稿如何产生（可验证的架构主张）

本件里的每一个数字都只经过这一条路径：

  1. 规划器只决定「写哪个学科、配哪些图」——它的输出里没有数字这个物种；
  2. 数值由查询工具从 ledger_long.parquet 取出，逐点附来源链；
  3. 图上每个点由引擎按 JSON spec 渲染，模型不接触坐标；
  4. 模型如给出图表声明，只允许 invert / include / zero_base 这类语义参数，轴范围永远由数据决定（代码里没有「纵轴上下界」这个字段）。

因此模型在本产线里的输出只有三种：查询、图表声明、正文草稿——草稿里的数字位是占位符，由工具回填、逐格可回读；馆员需拍板的判断句以细下划线标出（待审线）。（设计口径见 评审文档/19 §2.2）
