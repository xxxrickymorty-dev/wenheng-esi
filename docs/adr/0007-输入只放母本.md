# 输入只放母本：动态监测表的单一运行时输入与期次切窗

- **状态**：已接受（rick 2026-10-13 拍板；同日实现并验证）
- **关系**：修订 ADR-0004 的「建副本」落点与开跑输入；「唯一事实源 / 运行期只读 /
  按列追加不覆盖历史 / 受控写路径」全部继续有效。

## 背景

- 馆员每期**动态更新同一张表**《云大全学科排名、阈值动态检测表.xlsx》（按列追加，
  绝不覆盖历史）；7 月与 9 月的"表"其实是同一个文件的两个时点。
- 旧约定 `input/<期次>/监测表.xlsx`（ADR-0004 的当期副本）让"每期一张表"看起来像
  独立数据物种；历史期补跑（rerun_history）与 01/03/05 的产出证明**母本＋目标期次**
  即可完整复现（消费层按 `<= 期次` 切窗）。
- 消融实验（对话问答）暴露：期次题失分在**规划层**（不解析问句期次），与数据文件布局
  无关；把数据面收敛成一份母本反而让"07 不读 09"的口径更清晰。

## 决定

1. **`input/` 只放母本**：`input/云大全学科排名、阈值动态检测表.xlsx`——运行时输入
   （开发机与部署机同路径）；流水线 / 开跑口 / 问答回落 / 盘点 / e2e / 部署包都只读它。
   路径口径唯一实现在 `src/ledger.py`。
2. **每期不再另存表**：当期取数核对副本落 `out/_acquisition/<期次>/监测表.xlsx`
   （ADR-0004 的「审的＝写的」载体不变，只换落点）；上传开跑也落这里。
3. **期次显式**：`run_pipeline.py --period <期次>`（job 开跑必带）＝母本＋目标期切窗；
   大表/概述/图表/预测/省域/矩阵/报告全部按被跑期（"07 的报告不读 09 的数据"）。
4. **同步与预检**：「并入台账」成功后自动把馆员原件同步到 `input/`；
   手工改过原件跑 `tools/sync_input_ledger.py`；部署包预检核对两者 sha256，不一致拒打包。
5. **术语**：「台账 / 监测表」两个名字退役，统一叫**动态监测表**（见 GLOSSARY）。

## 代价（知情接受）

- 旧副本（07/09）已移入 `out/_acquisition/<期次>/`（保留为历史核对副本，不删）；
- 部署包新增 `out/_acquisition/`（取数状态 + 核对副本；首屏三步条与盘点要用）；
- 历史期（01/03/05）仍无核对副本——盘点「动态监测表」件按"该期数据已在母本里"判（filled）。
