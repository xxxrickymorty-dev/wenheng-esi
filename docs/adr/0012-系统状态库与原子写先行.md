# ADR-0012 状态入库分两步：先原子写，再建「系统状态库」，且不入数据面

- 状态：已采纳（2026-10-21，rick 定）
- 关联：`docs/specs/2026-10-13-台账镜像（SQLite）.md`、`docs/specs/2026-10-13-会话库（SQLite）.md`、
  `docs/adr/0007-输入只放母本.md`
- 前置：本 ADR 决策的落地票尚未开；ADR 只记「为什么这么定」，不记实施细节。

## 背景

运行期状态散在二十多个文件里（`out/_jobs/<id>/job.json`、`out/<期次>/approval.json`、
`review.json`、`audit_record.json`、`run_log.json`、`env_snapshot.json`，以及各处的 `*.jsonl`），
其中八处是裸 `write_text`（非原子），断在半截就是坏文件。仓里已经有两个 SQLite：
`out/_mirror/ledger.sqlite`（只读派生的台账镜像，后续票未做，目前只有 CLI 与测试在用）
和 `out/_sessions/sessions.sqlite`（会话记录）。rick 提出「加个 SQLite，后期迁 pgsql」。

规划过程中做过一次对抗性审查，结论改变了方案：**「入库」买到的是可查询与统一，不是安全**。
非原子写的低成本解法是已有的 `atomic_write_text`（`src/ai/_record.py`），一小时能覆盖八处；
而把状态收进库是「重构状态读写层」，量级更大。若不做这个区分，ADR 会替一个更便宜的方案背书。

## 决定

1. **先做原子写，再做库。** 把 `atomic_write_text` 提为公用助手，替换现有八处裸写，
   作为独立可验证单元先提交。它不是本 ADR 的附带项，是前置。
   （2026-10-22 补记：实际收口 12 处 = 第一批 8 处 + 第二批 4 处，后者是诊断报告、归档
   manifest、`server/jobs.py` 的预测选模快照、`run_pipeline.py` 的 meta 回填。）
2. **新库是「系统状态库」，不是数据面。** 动态监测表（母本 xlsx）仍是唯一事实源；
   运行期 LLM 不进数据路径不变；**ESI / InCites 原始包不入库**（9 GB 级原始证据，
   备份即整份复制、无增量，且一旦入库就失去「原件」的证据地位）。要多维查询原始明细，
   走 parquet + 只读查询，不建库。
3. **范围分批，先做 ②**：先收 `approval` 与 `review`（签单是唯一「丢了没法恢复」的状态，
   `review.json` 零测试读者）；`job.json` 随后入库（2026-10-21 第二批：任务记录在 `jobs` 表，
   `out/_jobs/<id>/job.json` 停写停读）；**`manual_inputs.json` 第三批入库（2026-10-22，schema 003）**：
   一行一处（`period, slot`）而不是一期一行，才能回答「谁在什么时候填的哪一处」，
   行序＝写入序，导出仍逐字节可比；`run_log.json`、`audit_record.json`、`env_snapshot.json`
   缓做——它们挂在确定性产物与 logpack 上，先入库会把产物路径与库路径搅成两套。
   `out/_forecast_choices/` 与 job 私有快照里的 `forecast_choice.json` **永不入库**：
   那是出稿时冻结的输入证据，必须不可变（同决定 2 对原始包的理由）。
   `progress.jsonl`、`ai_calls.jsonl`、`task_runs.jsonl`、`state_history.jsonl` **继续做追加日志留在文件里**
   （append-only 不需要事务，SSE 按字节偏移 tail，改成游标不划算）。
4. **`out/_acquisition/`、`flexible/` 中间态本期不收**（有 Windows `os.replace` 重试与真实并发坑）。
5. **stdlib `sqlite3` + 一个 store 模块收口全部 SQL，不上 ORM。** 但**不假装方言中立**：
   WAL、upsert、`json_extract`、自增都是 sqlite 专有，"迁 pgsql"的真实成本 = 重写 store 的 SQL 层。
   这条要写在代码注释里，免得后来人以为换连接串就行。
6. **表结构**：按域分表（`approvals` / `reviews` / …），既有结构化检索列（`period`、`actor`、`ts`），
   又留 `payload` 列存原文 JSON。**不存 `status` 列**——签单的 stale 判定必须每次现场
   glob + hash `out/<期次>/` 的产物（`server/approval.py`），库里缓存状态必然与文件不一致。
   （`manual_inputs.status` 是唯一例外，且同样**不是真相**：只记落库那一刻的三态，
   读回不返回、判定仍由 `workbench._fill_state` 现场算——见 spec 表结构。）
7. **迁移**：`migrations` 表 + 手写有序迁移函数。状态不可重建（重建＝丢审批），
   所以「版本不符就重建」在这里是错的。**版本高于代码时只读降级 + 页面明确告警，不拒启动**
   ——拒启动会让回滚也不可能（回滚代码就再也起不来）。
8. **并发**：`journal_mode=WAL` + `busy_timeout`，每个写操作一个短事务；**不加跨进程锁**，
   沿用「uvicorn 单 worker + 单任务」的既有约束。真需要多写者，那是迁 pgsql 的信号。
   库路径唯一口径放 store 模块（`db_path()`，可用 `WENHENG_STATE_DB` 覆盖），
   流水线子进程靠它拿到同一个库。
9. **只换存储，不换接口**：`server/artifacts.py` 那几个 `read_*` 的签名与返回形状不动；
   要改的是直接摸文件的那些调用点（请求路径上约十处、`e2e_check.py`、logpack）。
   错误代价不能翻倍——前端与 202 条 e2e 断言建在 `/api/*` 的形状上。
10. **切换的前提是两个工具，不是附加项**：`state_import`（幂等、可重跑、导入不删原文件——
    否则 `out/202607` 的已签状态一迁就没了）与 `state_export`（反向回退与审计）。
11. **库放 `out/_state/wenheng.sqlite`**，与 `_sessions` 同级、不跟期次走；
    加进 `tools/make_deploy_pkg.py` 白名单，且**打包前做 `wal_checkpoint(TRUNCATE)`**
    ——否则 WAL 副文件不带，部署包静默丢掉最近事务。
12. **镜像库不合并、不删**：它是 rick 点头过的规格，且属于数据面（只读派生）。
    本次与其零耦合，处置另记待办（复活接查询层，或删）。

## 后果

- 人看的导出件保留：`审批记录.md`、`审计记录.md`、logpack 改由库渲染，不再由状态文件顺手写。
- `server/e2e_check.py` 现有「字节级备份/还原 `approval.json`」的机制会失效，需改指测试库
  （`WENHENG_STATE_DB`）或改走库备份——这是切换的硬前提之一。
- 部署包会带上审批记录 = 带上馆员姓名，与「含姓名的文档不外发」口径冲突；打包需脱敏 actor
  或明确「演示包不外发」。（2026-10-22 已实现：打包时对副本脱敏 + 泄漏即失败）
  自由文本批注里的姓名**已在源头清掉**（2026-10-22，`tools/state_cleanup.py scrub-note`：
  202609 那条批注整条清空、只改 `payload` 一列、库行数不变，改前做了 sqlite 一致性备份）；
  打包的 `--redact-term` 因此退为出口兜底，不再是这件事的常规解法。
- `out/` 在根 `AGENTS.md` 属数据红线保护对象（「一律只读」）。运行期写 `out/_state/` 属于流水线本来的写行为，
  但评审口径需要一句现成的话顶回去：**红线禁的是为凑演示手改数据，不是禁运行期落状态。**
- 回滚要同时回滚代码、库、部署包三样，而 `state_export` 只在回退时才跑、测试最少——
  它需要一个反向 e2e 用例，否则这个风险只是被承认，没有被兜住。
- 改动会带动用例数与断言数，收尾按 `tools/doc_counts.py` 对齐。

## 考虑过但没选

- **上 SQLAlchemy + Alembic**：表只有个位数、schema 一年动一两次，收益撑不起依赖与心智成本；
  但迁移路径必须有，所以用 `migrations` 表而不是「版本不符就重建」。
- **统一宽表 `records(scope, period, kind, payload)`**：省事，但查不了「谁在什么时候签的哪一期」，
  而审批与复核的全部价值就在这句查询上。
- **原始包入库**：见决定 2。
- **双写过渡**：会制造两个真相，是这个项目最忌讳的形态；改为一次性切 + export 兜底。
