# 取数后「建副本 → 核对 → 并入」：主台账的受控写路径与顺序

- **状态**：已接受（rick 2026-09-29 拍板；界面稿 X1 修订版已出，实现随 X2/X3）
- **关系**：CONTEXT.md 红线 2 的受控扩展——「唯一事实源 / 禁 openpyxl 存盘 / 按列追加不覆盖历史 / 运行期只读」全部继续有效，本 ADR 只新增一条**受控写路径**。

## 背景

- 主台账《云大全学科排名、阈值动态检测表.xlsx》是唯一事实源；历史上由馆员手工贴表。
- 2026-09-23 起有清洗链（`tools/clean_ledger.py`，`--out` 写副本 / `--write` 写主台账）能自动写台账，
  但顺序是「**先写主台账、再另存副本**」，写入前没有审核闸；给馆员的 v3 说明又已承诺「要贴的列都能自动生成」——
  口径与保障不匹配。
- 取数自动化（9 组约 64 份、逐文件核验）打通后，rick 定调：取数数据**不得未经核对直接进主台账**。

## 决定

1. **建副本**：取数核验通过 → 自动清洗 `--out` 新建 `input/<期次>/监测表.xlsx`——只写当期列；主台账不碰；历史列一字不动。
2. **核对**：馆员核对「本期新增列核对表」（工作区页面；也可直接打开监测表文件）。
3. **并入**：核对通过后按键「并入台账」——以**已核对副本为准**写入主台账（审的＝写的）。
4. **机械保证**（缺一不可）：写前备份；冲突拒写（占位空列可直接填；已有不同值需人裁决并二次确认才覆盖）；
   **列白名单**（只允许写当期列）；**旧列逐格比对**（写后旧列必须一字不变）；写后接 `src/ledger_patch.py` 的 `audit()` 四查。
   任一项不过即停、待人工，不给「静默继续」。
5. 生成台用**已核对的快照**做开跑输入；**运行期流水线对台账仍只读**（sha256 护栏不动）。
6. 口径与用词：「下载完成≠台账已更新：先核对，核对通过才并入」；
   界面词＝「核对本期数据 / 并入台账 / 本期监测表」（「贴表」「入库」当动作名退役）。

## 为什么

- **审的 = 写的**：核对的对象与写入的值是同一份副本，避免「审 A 写 B」。
- **自动化不牺牲把关**：人按键触发（写操作永远由人发起）、审核闸在前、机械核对在后。
- **复用现成机制**：清洗链本就有 `--out` / `--write` 两档；`audit()` 四查已存在但此前无人调用。

## 代价（知情接受）

- 多一步人工核对（原先贴表也是人做——净负担未增，人从「搬数据」移到「核对」）。
- 需新增「并入」小工具与取数相关新接口；**期次列表/详情要支持未出稿的当期**（现详情要求已出稿的 `out/<期次>/red_slots.json`）。
