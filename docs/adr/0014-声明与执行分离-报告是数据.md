# ADR-0014 声明与执行分离：报告是数据，不是代码

- **状态**：待 rick 确认（2026-10-28 起草，今日七条决策的收敛）
- **关系**：承接 ADR-0005（自主性边界）——0005 管「模型能不能碰数」，本决定管「报告长什么样、存在哪」。
  两条正交，叠加后才是完整边界：**模型不碰数，报告不进代码。**
- **关联分析**：`架构图/` 六份（老师架构图对齐 / 业务地图 / harness 选型 / 目标架构 / 可推广性 / L2 异模板 / 灵活定制）

## 背景

四个压力同日到来，指向同一个病灶。

1. **平台化**（老师）：文衡不该只是一份报告工具，该是能接能扩的底座。
2. **灵活定制**（馆员）：每期在网页上自选章节与图表，不再一成不变。
3. **推广**（他校）：同体系（ESI／InCites）但模板不同。
4. **扩展**（自己）：后续要加阈值预警、动态简报、对标分析。

病灶：`src/agent/flow.py` 的 `STEPS` 是**全局唯一事实源**。翻译成产品语言——**这个系统只能有一个产品**。
每加一份报告、每换一所学校，都要动这条主干。

## 决定

1. **报告是数据。** 每份报告一份声明（`reports/<id>.spec`）：数据源、步骤序列（只引用插件名）、
   人审卡点、产物清单、槽位映射、口径版本。**加报告＝加声明，不改主干。**
2. **执行器可换，声明不动。** 现在用 for 循环（零风险）；需要断点续跑／并行／暂停等人签时换
   LangGraph，**图由声明生成，不手写**。验收判据：**换执行器时 spec 一字不改。**
3. **插件层收敛为一张注册表**（终态）。今天是四张：`agent/tools.py` 13 ／ `ai/_dialog.py` 2 ／
   `server/mcp_aiqa.py` 3 ／ `flexible/queries.py` 5。过渡期只造「工具账本」（一页索引，
   标注输入／输出／权限／只读），**不动执行代码**。
4. **校本差异进 `school/` 三份配置**（`data.yaml`／`report.yaml`／`org.yaml`）＋ `wenheng doctor` 自检。
   换学校只换目录，不改代码。校名当前散在 **58 处／19 个源文件**（`grep -ro 云南大学 src/ server/`，
   排除 `__pycache__`），收进 `org.yaml` 是一级任务，
   验收法：源码出现校名字面量即测试失败（白名单只留 `org.yaml` 加载处）。
5. **锚点用名字不用坐标。** 模板标注走 Word `w:sdt` 内容控件（`w:tag` ＝ 语义键），渲染器零行列号。
   现状 `red_slots.json` **721 条全是 `T01/r1c0` 式坐标**，换模板即静默全废（填错格子不报错）。

## 表达力守则（本 ADR 的硬边界）

声明层只允许四件事：**顺序／条件跳过／人审卡点／产物清单**。
**不允许表达式，不允许脚本。** 需要复杂逻辑 → 写插件。

理由＝dbt 的教训：配置一旦能写逻辑，迟早变成第二门语言，比直接写代码更难维护、更难测。
守不住这条，声明层会从资产变成负债。

## 为什么

- **「灵活」与「可复现」不矛盾**，条件是**决定发生在跑之前**。同 spec 同产物；模型在产线之外
  把话翻译成声明，人不满意就改声明，改完再跑。
- **反过来算一遍**：5 步 × 每步 3 个候选 ＝ 243 条路径，只有 1 条对；模型每步 95% 正确，
  整链 0.95⁵ ＝ **77%**。对一份 704 槽位、要盖章的报告，77% 等于不可用（错一格整期返工）。
- **平台的判据不是功能多**，是「第 6 个应用的边际成本 ≤ 第 1 个的 25%」。
  声明层是唯一让边际成本递减的形状；框架（LangGraph／deepagents／Octop／DeepSeek Harness）
  都只让**执行**更可靠，不改变这一条。

## 否决（连同理由，防止反复）

1. **不换运行时。** LangGraph 当内核：图是代码，N 份报告＝N 张手写图，扩展性问题原样保留；
   DeepSeek Harness（264k★）／AgentScope／Octop 是 TS 栈，而文衡的重活是**文档工程**
   （python-docx 母版替换、openpyxl、百张图），Node 侧没有等价物。
2. **不引框架来「获得技能」。** 技能是文件格式（Agent Skills 规范 / `SKILL.md`），
   pi、AgentScope、deepagents 三家共同实现。抄格式 100–150 行，不装依赖。
3. **不让模型进产线编排。** ADR-0005 的延伸；已用 243 路径 / 77% 量化过。
4. **不把五步拆成五个 MCP 工具。** MCP 调用是秒级，渲染图表是分钟级；要暴露就作业化
   （开工 ＋ 查进度两件套，复用 `server/jobs.py` 语义）。
5. **不做 SaaS。** 报告要盖章：章是学校的、责任是馆员的、数据是订阅库的。
   半自动（初稿 ＋ 红件清单 ＋ 人签单）才是正确边界。

## 后果

- 新增「声明层」这一层：spec schema、加载器、**三向校验**（声明有模板无 tag → 必报；
  模板有多余 tag → 警告；两边都有但类型不符 → 必报），以及把 spec 存进期次档案。
- `flow.py` 的 `STEPS` 从「全局常量」降为「标准报告声明的默认值」——**仍是默认产线的唯一事实源**，
  红线不变（`test_agent_flow.py` 的防漂移断言照常有效）。
- 加报告的成本从「改主干」降为「写声明」；换学校的成本从「改 12 个文件」降为「换目录」；
  灵活定制的成本从「不可复现」降为「一行 spec」。
- 短期多一层间接：看一处逻辑要看两个文件（声明 ＋ 插件）。这是知情接受的代价。

## 未决

1. **spec 格式**：YAML（非程序员可改）vs Python 常量（可复用常量与类型）。倾向 YAML ＋ 类型校验。
2. **语义键命名规范**：`disc.plant_animal.rank_intl` 的分段与缩写表，需与现有 `DISC_CN_ALIAS` 对齐。
3. **四张表合并时机**：建议决赛后（先账本）。
4. **换 LangGraph 的触发条件**：建议「多期并行 ＋ 断点续跑成为刚需」时才动，且以「spec 不改」为验收。

## 与既有 ADR 的关系

| ADR | 关系 |
|---|---|
| 0005 自主性边界 | **正交叠加**：0005 定「模型能做什么」，0014 定「报告存在哪」 |
| 0008 对话层零数字 | 被 0014 继承：声明层同样零数字（只引用插件名，不含数值） |
| 0012 系统状态库 | 期次档案（含 spec）应进同一套状态库，不新起一层 |
| 0013 台账镜像删除 | 印证同一取向：**不为一个消费者养一层壳** |
