# 取数任务的活性判据与状态文件并发写：pid 判活、写重试、崩溃落 failed

- **状态**：已接受（rick 2026-10-19 开「第一批」时定；同日实现并验证）
- **关系**：补 ADR-0004 的护栏——只管状态文件 `out/_acquisition/<期次>.json` 的**写入
  健壮性**与 `op`（任务进度）的**活性判断**；「人按键触发 / 审的＝写的 / 台账只读 /
  台账一字节不碰」全部不变。
- **上位口径**：CONTEXT.md 红线 2（受控写路径）与红线 6（GET 不改状态）。本 ADR 不破任何一条：
  自动落 `failed` 只发生在**写动作路径**（人按键触发的 POST），GET 角只读。

## 背景

2026-10-17 取 202609 时出了两起事故（都能复现，日志 `out/_acquisition/202609-fetch.log`）：

1. **状态文件原子替换撞并发读 → 整个取数进程暴死**。`write_state()` 用 `tmp.replace(目标)`
   落盘；Windows 上目标文件正被别的句柄打开（取数台前端每 4 秒轮询读一次，服务端 `load_state`
   开着它）时，`os.replace` 抛 `PermissionError: [WinError 5]`。
   实测（一边读一边写 200 次）：**139 次失败**；202609 的取数就是死在这一步，`esi-subjects`
   组刚跑完、进程直接退出。
2. **暴死后 `op.state=running` 变僵尸**。判定「任务还在跑」的唯一口径是
   `server/app.py::_acq_op_running` 的「状态文件 1 小时内有改动」——进程死了没人写、
   时间没到没人清：取数台一直显示「下载数据中」，新任务被 409 拦住最多 **1 小时**。
   `202609.json` 至今挂着 `op.state=running`（10-17 13:02 的崩点）。

并发读不是异常，是设计内常态（任务在跑时前端就在轮询）——写方必须扛住读锁，而不是被读方拖死。

## 决定

1. **状态文件写入带重试**：`src/acquisition_state.py::write_state()` 的原子替换
   重试 ≤5 次、间隔 100ms（只吞 `PermissionError`，仍失败才抛）；`load_state()` 读同样
   重试 ≤3 次。写入仍是**唯一写口**，状态形状不变。
2. **`op` 记 `pid`**：取数流程每次写 `op` 都带写方进程号（`tools/acquire.py::_set_op`）。
3. **活性＝ pid 判活**，唯一实现 `src/acquisition_state.py::pid_alive()`（server 与 tools
   共用同一份）：`op.state=running` 且 pid 已不存在 → 服务端在**写动作**处自动落
   `op=failed`（「任务进程已退出（上次运行中断）」）并放行新任务；没有 pid 的旧状态回退
   时间口径，阈值由 1 小时收紧为 **15 分钟**（`OP_STALE_SECONDS`）。
4. **取数流程崩溃自己落 `failed`**：`tools/acquire.py` 顶层兜底——任何未捕获异常在退出前
   把 `op` 写成 `failed`（异常类型 + 一行原因），不再等时间口径。
5. **权限口径追认与同步**：取数八连（`acquisition/browser/start/open/retry/copy/merge/preflight`）
   与 `outline` 对操作员开放（追认 `34d7ca1`，2026-10-17）；契约文档 §2 #26、§7.1 权限矩阵与
   `server/e2e_check.py` 同步（原断 403 的两条：只读口改断 200、写探针改走非法期次 404、
   零副作用）。

## 代价（知情接受）

- pid 复用理论上会误判「还活着」——概率极低，且 15 分钟时间兜底仍在；
- **不代 UI**：强杀/断电（来不及落 `failed`）时，取数台文案仍会停格在「下载数据中」，
  直到人按键触发（那时自动落 failed）或 15 分钟兜底放行。取数台的「疑似中断」提示
  属前端批次，需先出静态稿（web/AGENTS.md 交付纪律 1）。

## 落地补记（2026-10-19 晚，前端批次）

- 静态稿 v2 经 rick 审定（`web/mockups/取数核验-下载控制（静态稿）.html`，三态可切）：
  文案去括注、「停止下载」行内二次确认（复用 `ConfirmButton` 口径）、红色。
- 落地的两件：
  1. **GET 只读加 `op.liveness`**（`alive / dead / stale`，仅 running 时出现）——前端据此
     在**不改状态**的前提下把「疑似中断」显示出来（`dead`＝进程没了；`stale`＝无 pid 且
     超 15 分钟没动静，覆盖本 ADR 之前留下的旧僵尸）。
  2. **`POST …/acquisition/stop`**：按 `op.pid` 停进程树（Windows `taskkill /T /F`；
     POSIX 进程组——`_acq_spawn` 同步补 `start_new_session`）→ 落 `failed`（note 前缀
     「已停止」）；僵尸直接落 `failed`（「上次运行中断：…」）；没有在跑的任务 → 409 不写状态。
     已下载文件保留，「继续下载」只补缺——语义词是**停止**（可续），不是不可逆的终止。
- 写动作路径的自动结清（`_acq_op_running`）与停止端点共用同一份 `_acq_op_liveness` 判断。
