# 对话是控制面，表格是证据面

- **状态**：已接受（rick 2026-10-10 拍板；grilling 三轮）
- **关系**：ADR-0005（自主放「决策与校验」、不放「算数与事实」）在前门上的展开；CONTEXT.md 红线 1 不变。

## 背景

- 诉求：把整个系统做成一个对话框——「帮我做 9 月的报告」→ 认期次 → 盘点 → 引导取数 → 核对 → 出稿，工作台不再只是工作流的形式。
- **三块料已具备**：能力口 `qa`（问文衡）、取数工具（`tools/clarivate_*_fetch.py`，CDP 驱动真 Chrome）、生成台三步条 + 确定性流水线。缺的是把它们**串起来的编排线**。
- 事实边界（实核）：期次＝数据截止月；台账有数据的最后一个是 `202607`，**`202609` 是占位列（未发布）**；`input/` 里 202609 只有监测表，缺顶尖论文清单。

## 决定

1. **对话是前门，不是唯一入口**：表格页（对勘本 / 红件清单 / 签单）保留路由，从「必经」变「**被叫出来**」。
2. **对话只做指挥**：认期次（含消歧）、盘点、引导取数、触发流水线、解释；**不产生任何数字**。
3. **证据面不搬进对话**：核对跳表格页，核完回对话继续出稿——ADR-0004 的门**由人签**。
4. **期次只有一个含义**（数据截止月）：不支持「出稿月」说法；**该期数据未发布/不可用 → 停下反问**。
5. **诚实的边界**：登录下载是**人的步骤**——能驱动的驱动（CDP 开真 Chrome），登录那一步明说「这步得你来」。
6. **全量留痕**：每轮对话 + 每次工具调用进 `ai_calls` / 运行档案，**不新开账本**。
7. **槽位级记忆**：只记期次/意图（可显示、可清、可审计）；**不记自由上下文**。
8. **确认门只有一处**：覆盖已有产物；其余（盘点、驱动取数、出稿）说了就做。

## 为什么

- 242 格对勘、红件清单、签单是**把关的实物**，气泡里看不了；把它们搬进对话 = **把关消失**。工作台会干净，是因为页面从「必经」变「按需」。
- 对话是控制面，模型只在控制面活动——**ADR-0005 的红线原样成立**。
- 盘点判的是「件在不在」，核对判的是「数对不对」——两件事，各有各的门。

## 代价（知情接受）

- 系统有两副面孔（对话 + 表格），不是「一个框搞定一切」。
- 对话的理解错误会**静默传下去**（认错期次 = 出了错期的报告且没人会发现）。三条对策：**说出解释**、**数据不可用即停**、**全量留痕可回放**。
- 取数链路只在**有浏览器、有人在场**的机器上成立（公网服务器上只能报缺）。
