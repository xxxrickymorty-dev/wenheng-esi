# 前端技术栈放开：新增 `web/` 工作区系统（React + Vite），旧站继续冻结

- **状态**：已接受（2026-09-22，rick 拍板）
- **修订对象**：`评审文档/09-技术栈与前后端边界决议.md`（WH-DOC-09）§0 / §6 / §7
  —— 该文 v1.0 的「前端零框架、零构建、零 CDN」**继续适用于旧站**（`server/` 模板与 static、仓库根），
  新增目录 `web/` 不受其约束。WH-DOC-09 正文的 v2.0 修订**待新系统可演示后再做**（赛前不动评审材料）。

## 背景

WH-DOC-09 §7 列了四条「重新评估」的触发条件，本次触发**不在其中**，是新增的第 5 条：
系统形态从「单页演示站」变为**多工作区工作系统**——ESI 报告 / 学科发展态势报告 / 年报，
支持一键生成、在线审核更改、AI 辅助分析；且比赛评审需要可演示、可验证的工作量。

§5 的五条硬理由（离线是硬约束、产物要能内联成单文件、体量、评审要读代码、与维护者匹配）
**在新形态下依然成立，但适用对象变了**：它们约束的是**离线演示件**（`F-藏书阁` 单文件原型、
`collation-demo.html` 快照），而不是整个系统。旧站自身继续满足全部五条。

## 决定

1. 新增 `wenheng/web/`：**React + TypeScript + Vite** 单页应用；Tailwind CSS 做样式层，
   shadcn/ui 做组件层（组件按需复制进仓库，不是运行时依赖），GSAP 做动效编排。
2. 构建在**本机**完成，产物 `web/dist/` **入库**；服务器仍不装 Node，FastAPI 以静态目录托管在 `/app`。
3. 后端保持 FastAPI 单栈不变。新工作区经 `/api/*` JSON 接口取数，
   继续遵守 B-1（GET 不改状态）、B-3（数字只来自后端）、B-4（产物只经白名单端点）、B-5（实时只走 SSE）。
4. **旧站不改不迁**：`server/` 的模板与 static 继续零框架零构建零 CDN，新系统只做加法。
5. 守卫调整：`tests/test_stack_contract.py` 的「零 JS 依赖」四条改为**限定旧站作用域**；
   为 `web/` 新增两条护栏——`node_modules` 不入库、构建产物不得含外链。

## 被否掉的选项

| 选项 | 否掉理由 |
|---|---|
| 继续零框架（Jinja + 原生 JS） | 多工作区共享状态与组件复用会失控；§7 第一条触发条件（单文件 >1000 行且 3+ 页面共享状态）已在逼近 |
| Vue 3 / Svelte | 生态面与 AI 协作面更小；不反对，作为备选记录 |
| Next.js 等 SSR 元框架 | 后端是 Python，SSR 无意义；静态 SPA + FastAPI 托管已足够 |
| 一次性重写旧站 | 比赛期（9/30 材料截止、10 月底演示、11 月答辩）风险不可接受；旧站是唯一不能坏的东西 |

## 后果

- 新增一条构建链：本机构建 → `dist/` 入库 → 部署时随包上传。`server/deploy/deploy_linux.sh` 需补 `web/dist`。
- **改 `web/src` 必须 `npm run build` 并提交 `dist/`**——忘了构建，演示站会继续跑旧代码，且不会报错。
- 评审材料（WH-DOC-09 及 HLD/LLD 相关章节）的 v2.0 口径，等新系统可演示后同步。
- 离线单文件件（`F-藏书阁` 原型、`collation-demo.html`）**继续保留**，作为评审现场兜底。
