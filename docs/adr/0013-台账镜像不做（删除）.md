# ADR-0013 台账镜像不做：连 spec / 模块 / CLI / 测试一起删

- 状态：已采纳（2026-10-22，rick 定）
- 关联：取代 `docs/adr/0012-系统状态库与原子写先行.md` 决定 12；原规格
  `docs/specs/2026-10-13-台账镜像（SQLite）.md` 随本决定删除

## 背景

`src/ledger_mirror.py` + `tools/build_ledger_mirror.py` 把母本 xlsx 确定性重建成
`out/_mirror/ledger.sqlite`，但后续票（引擎接镜像、内核白名单视图）一直没开工——**只有 CLI 与测试在用**。

## 决定

**不做，整条删除**，不留降级路径：

- 规格：`docs/specs/2026-10-13-台账镜像（SQLite）.md`；
- 代码：`src/ledger_mirror.py`、`tools/build_ledger_mirror.py`、`src/ledger.mirror_path()`；
- 测试：`tests/test_ledger_mirror.py`（10 例）；
- 数据：`out/_mirror/ledger.sqlite`（派生物，不在版本库、不受数据红线保护；
  红线保护的是 `out/<期次>/` 与原始包）。

取代 ADR-0012 决定 12。决定 12 的历史措辞不改，处置以本 ADR 为准。

## 为什么不留着当死代码

它与 `out/<期次>/ledger_long.parquet` **同数据、同解析函数**（`parse_ledger.long_table()`），
只是两套壳；项目刚把「状态库」（`out/_state/wenheng.sqlite`）立成唯一的数据库，旁边再躺一个
`ledger.sqlite` 必然被搞混。唯一真实用途（溯源接口每请求重解析母本）应该在**那一个接口**上解决，
而不是为一个接口养一层库。死代码不会被维护，只会让后来人以为数据面还有第二个入口。

## 后果

- 溯源与查询仍走 `ledger_long.parquet`：它已是同一口径的派生物，按期次切窗即可；
  逐格回读仍走 `parse_ledger` / `tools/verify_report_cells.py`。
- 真需要 SQL 查询层时按原 spec 的 ETL 思路重做：母本 → `long_table()` → 长表 → SQLite，
  确定性 `content_sha256` 可校验。口径函数没删，要重建的只是壳。
- 数据面入口只剩一个：动态监测表（唯一事实源）+ 当期 `ledger_long.parquet`。
- 测试用例数随之下降，收尾按 `tools/doc_counts.py` 对齐。
