# 报告类 Agent 的自主性边界：自主放「决策与校验」，不放「算数与事实」

- **状态**：已接受（rick 2026-10-10 拍板；完整设计见 `评审文档/31-报告类Agent自主性设计（v0）`）
- **关系**：CONTEXT.md 红线 1（运行期 LLM 不进数据路径）的显式化——把「一条红线」升格为「可复用的设计原则」，供所有后续 agent 工作引用。

## 背景

- 产品化要「体现 agent 自主性」，但文衡唯一打不烂的牌是「逐格可回溯、可复现」。
- 外部对照（Clarivate WoSRI，2026-10-08 试用）：agentic 平台普遍把模型放进数据链路，代价是口径漂移（同一问题两种口径）、不可复现（年份/文献类型随问随变）、小样本结论不稳。

## 决定

1. **自主面**（可以放）：理解意图、规划、选工具、判异常、决定何时交人、自审。
2. **确定性面**（绝不放）：取数、计算、预测、出图、数字注入——一律由工具产出；模型只**选**不**造**。
3. **固定产线不上多 agent**；多 agent 只长在开放式灵活产线，前置条件 =「计划可审 + 每步有账 + 有金标评测」。
4. **三条红线不变**：运行期 LLM 不进数据路径 / 台账只读 / 固定产线主干硬编码（`flow.py` STEPS）。
5. **升级阶梯**：固定产线顶到 L2（自愈能**提出**规则草稿，馆员 `approved_by` 签后入库）；灵活产线顶到 L3（planner + critic 成环）。

## 为什么

- 「自主」与「可复现」不矛盾：**被固定的是数与事实，被放开的是判断与编排，而判断本身也记账**（`agent/trace.py` + `ai_calls` 留痕 → 可回放）。
- 一旦让模型碰数，WoSRI 类「口径漂移、不可复现」的坑会全数进来，而逐格回溯正是文衡的信任基础。

## 代价（知情接受）

- 「像 agent」的观感上限被压低：模型不能自由发挥。
- 每个新能力都要先回答「它的自主面在哪、怎么记账」，设计成本前置。
