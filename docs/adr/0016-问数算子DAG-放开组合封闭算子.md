## 背景

问数（`src/aiqa_engine.py`）与灵活报告查询层（`src/flexible/queries.py`）
目前是 **kind 白名单**：一个问题类型注册一个 kind + 一个证据渲染器
（`ai/_evidence.py` 的 `_RENDERERS`），问题**实例**（任意期次 × 学科 ×
指标）开放组合，问题**类型**封闭。先例：compare 当初不在名单，
支持它＝显式登记 kind + 补证据渲染器。

这带来真实代价：**组合型问题答不了**。例：
「化学近三期的 1‰ 阈值差距在拉大还是缩小？」——不是任何已注册 kind。

pi 式「写代码跑数」的完全自由方案维持否决，理由不变（哑失败 /
确定性验收 / 数字夹带实测会发生）。

**v1 的事实错误，此处更正**：`queries.py` 的 `SCHEMA["kind"]` 实有
**八个**算子（`series / at / compare / delta / events / anomaly /
overall_rank / scope`），v1 称「六个」且漏列 `overall_rank`。
更重要的是：**上例拆不成现有算子**——它需要「每期差距序列」（学科
被引 − 1‰ 阈值，逐期求差再判方向），而 `delta` 只算一对期次、
`series` 只有首末两点 `change`，`datasource.METRICS` 里没有「阈值差距」
这个派生指标。v1 声称「每步都是已有算子」与代码事实不符。

## 决定（v2，分期采纳）

### 一期（先行）：参数化 kind，不建 DAG

1. **登记派生算子 `gap_series`**（两指标逐期差序列 + 方向判定）+
   一个证据渲染器。这是上例所需的最小增量：登记成本与 compare 先例
   同一轮，零新增引擎机制（无 DAG 解析、无成环检测、无逐节点留痕）。
2. **触发条件**：一期落地后积累 2–3 期真实问数中组合型问题的频率
   与形态。频率低 → 停在一期，按需逐个登记（问题类型仍封闭）；
   频率高且输出形状可枚举 → 启动二期。

### 二期（条件触发）：算子 DAG

模型的工作从「选一个预制 kind」升级为「用封闭算子拼执行图」，
执行、取值、渲染全部仍归引擎。

3. **算子集封闭**：只有引擎登记的确定性算子可入图（八个现有算子为
   底 + 一期起的派生算子）。算子登记制不变，且**对齐自愈规则库的
   授权机制**：登记须带参数 schema 与确定性实现，`approved_by` 为空
   不执行（同 `rules/repair_rules.yaml` 的 `RULE_UNAPPROVED` 口径）。
4. **模型参数面零数字（精确定义）**：
   - **期次不进模型面**——沿用 `_plan.py` 口径，期次由系统解析或由
     上游节点传递；「最近 N 期」的 **N 同为系统侧档位**
     （{3, 6, 12} 命名档），不进模型面；
   - **节点标识符非数字命名**——节点 id 一律字母命名（如
     `chem_rank`）；数字 id 会被数字盾打穿，schema 校验拒收；
   - **数值参数一律枚举档位**——如 `anomaly.threshold` ∈
     {宽松 / 标准 / 严格}，档位 → 确定性数值的映射在系统常量表；
     `compare.top` 同理取档位（{3, 5, 10} 内命名档）；
   - 由此模型输出可整体过数字盾（数字 → `[[n]]`）而**无需还原任何
     参数数字**；出现白名单外键、越界档位 → 当场拒、回落规则规划器。
5. **节点可引用性标志**：每个节点带 `cite ∈ {yes, no}`；
   `scope` / `anomaly` 默认 `no`（对齐 `queries.py`「规划依据、
   非可引用数值」的既有定位）——`cite=no` 的节点只作图内输入，
   其输出不进回答正文；**cite 随边传播且只降不升**：`cite=yes`
   节点**不得消费** `cite=no` 节点的输出（否则规划依据数值经图内
   转为可引用），违者校验当场拒。
6. **渲染器按形状登记，收益如实陈述**：形状集封闭且刻意保持小
   （以 `_evidence.py` 现有 kind 渲染器为底）。**组合开放的是查询**，
   不是呈现——同形状可由不同算子组合供给（一期登记不了的
   「差距序列走势」在二期由 `gap_series` 节点直接供给既有序列形状）。
   v1 声称「拼法自由所以不用逐类型登记」，本版收回：登记成本从
   「问题类型」降到「输出形状」，**不归零**。
7. **执行确定性与一本账**：逐节点按图求值，参数化、只读视图，
   取值仍只出台账——执行**仍走 `queries.py` 这唯一入口**，
   「LLM 拿数唯一入口」口径不变；叶子数值登记进
   `flexible/provenance.py` 证据账。每个节点的输入引用与输出值留痕。
   **衔接落到底**：`gap_series` 类派生序列**逐点**走
   `provenance._record_derived(inputs=…)` 登记（现接口只收单值、
   序列登不进——登记面按逐点扩展，不改证据账结构）；
   `trace_check` 目前单指标回读，双指标差值点会误判坏——
   派生节点声明 `inputs`，核对按 inputs 逐项回读。
8. **留痕与回放**：`ai_calls` 记 capability、mode（dag / fallback /
   rule 如实）、**DAG 规格全文 + schema 版本号**（版本号进规格，
   向后兼容规则：新增算子＝minor，改语义＝major、拒旧规格回落规则）。
   回放判据：同一期次同一 DAG 规格重跑，节点输出确定性一致，
   纳入 `verify_demo_run.py` 同级的确定性验收。
9. **离线回落**：无 key / 能力开关关闭 → 模型不画图，规则规划器
   原样兜底（演示站逐字不变）；开关跟随既有 qa 能力（ADR-0008 同款）。
   **回落语义与 `_plan.py` 供应商强制口径对齐**：`strict` 档下
   模型失败抛 `AIRequiredError` **不回落规则**（如实呈现失败）；
   回落仅发生在 `auto` 档与「拒收类」失败
   （schema / 白名单 / 档位越界 / cite 违规）。

## 为什么

- 一期用一轮登记成本解决眼下这一个真实例子，不预支二期复杂度
  （工程原则 1/3：从最小可用开始）；
- 二期只在「组合型问题实测高频」时启动——把 v1 的判断失误
  （一个例子撑一套机制）改成由使用数据触发的决策；
- 模型自由度仍限定在画框内：算子封闭、参数零数字、形状登记、
  可引用性显式——数字路径纹丝不动。

## 代价（知情接受）

- 一期也要设计 `gap_series` 的口径（哪个指标对哪个阈值、
  差距用什么单位）与渲染器；
- 二期是真机制成本：DAG 解析、成环检测、逐节点留痕、schema
  版本化、金标测试（每算子 × 每形状至少一例）；
- 「合法但无意义」的图与填错参数仍然可能——对冲：
  说出理解（回显模型拼的图意）+ 校验拒越界 + `ai_calls` 可回放。

## 明确不做

- 不引入任意代码执行；
- 不碰报告初稿数据路径——本层只服务问数 / 对比线；
- 不新增部署旋钮：开关跟随既有 qa 能力；
- 二期不在一期验证触发条件前启动。
