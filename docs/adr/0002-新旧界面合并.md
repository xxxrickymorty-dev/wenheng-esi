# 新旧界面合并：老站页面逐个下线并 302 到新工作区系统

- **状态**：已接受（2026-09-24 执行完成；rick 2026-09-23 拍板）
- **修订对象**：ADR-0001 第 4 条「旧站不改不迁」——其余条款继续有效
- **执行依据**：`docs/老站下线清单（阶段 2）.md`（前端整理、后端执行；§九 有逐批回填）

## 背景

阶段 0（视觉统一）与阶段 1（功能迁移）完成后，新工作区系统 `/app/` 已承接老站全部**日常**功能。
两套界面并存造成**风格与入口分裂**（方的 vs 圆的；点「打开报告」被送去老站），
重复的功能界面从「保险」变成了「负担」。本 ADR 记录阶段 2：老站页面**逐个下线**。

## 决定

1. **老站页面逐个 302 到新工作区**。映射表是 `server/config.py` 的 `LEGACY_REDIRECTS`
   （单一事实源，路由与测试都读它）；已下线子集记在 `LEGACY_LIVE`，
   `server/e2e_check.py` §3.5 逐条验收落点。用 **302 临时重定向**（不是 301）——
   外部收藏、演示 PPT 旧链接、历史文档都还能用。
2. **老站只保留基础设施**：`/api/*`、`/download/*`、`/chart/*`、`/qr.png`、
   `/login`、`/logout`、`/healthz`，以及离线演示件 `collation-demo.html`（快照）。
3. **P2 三页本轮不下线**：`/p/{期次}/archive`、`/p/{期次}/flexible`、`/forecast`
   ——新站没有等价物，先保留原样，迁完再进第二轮（清单 §五）。
4. 下线**一次只动一组页面**，每步跑 `e2e_check.py` + `pytest -m "slow or not slow"`，
   绿了才提交；每批一个独立提交，回滚 = revert 那一个。

## 为什么推翻 ADR-0001 的「旧站不改不迁」

1. 两套界面并存造成风格与入口分裂；
2. 阶段 0/1 已把日常功能全部迁完并逐项验证，重复界面成了负担而不是保险；
3. 演示与评审只剩一套入口，讲解与维护成本都降一半。

## 代价（知情接受，rick 2026-09-23 已确认）

- **失去「不依赖 JS 也能签发/填写」**：真正无 JS 的写路径只剩保留页（P2 灵活报告）
  的一个表单；下线后写操作全依赖 JS（走 `/api/*` JSON）。兜底只剩
  `collation-demo.html` 快照（只读）。
- 老站 e2e 与栈契约测试在迁移期会有一次**覆盖空窗**——以「一次只下线一组页面 +
  每步全量测试 + e2e 改为 302 落点验收」对冲。

## 后果

- 删除老站模板 7 个：`index` / `job` / `workbench` / `collation` / `redslots` / `charts` / `trace`；
  静态 `index.js` / `job.js`。`collation.css` / `collation.js` **暂留**（离线快照依赖它们）。
- 表单 POST 收敛为 `/login` 与 `/p/{期次}/flexible` 两条；其余写路径全部走 JSON API。
- 守卫更新：`tests/test_stack_contract.py` 钉 302 映射表、`LEGACY_LIVE` 子集、
  P2 三页不进映射；e2e 逐页内容断言改为 302 落点断言。
- **待办**：P2 三页迁移、前端全站走查（新站不再有任何指向老站的链接）、
  `collation.css/js` 是否内联进快照（内联后即可删）。
