## 二、不符或存疑

### E1（blocker）改了 `1040-1044` 关不掉入口，第二、第三处漏改

- **ADR 原话**：「`qa_direct=False` 时整套回落模型作答（`_dialog.py:1040-1044`）」；决定 1「撤销 `_dialog.py:1040-1044` 的『关着也必须模型作答』，改出『问数入口已关闭』说明」。
- **代码实际**：1040-1044 只处理 `kind=="unclear" and qctx` → 提升成 `query`。真正让「整套回落」成立的是 **1034 那条门取假**：`qa_direct=False` → 条件不成立 → `kind` 保持 parse 出的 `"query"` → `_dialog.py:1090-1097` 走 `_query_reply`（只做路由）→ 服务器 `server/routes/dialog.py:417-427` 再 `ai.run("qa", …)` 由模型作答。`tests/test_dialog_aiqa.py:491-493` 钉的就是这条路（断言 `kind=="query"`），而该用例的问句带指标、根本不经过 1040-1044。
- **准确改动点共四处**：`_dialog.py:1034-1039`（门）、`1040-1044`（`unclear` 提升）、`1090-1097`（`query` 分支）、`server/routes/dialog.py:417-427`（服务器再路由到 `qa`）。只改一处＝验收 2「不调用模型」必不过，且「入口关闭」是假的。

### E2（blocker）「数字唯一来源＝`execute`」在同一条问答链上还有两条不走它的取数

- **ADR 原话**：决定 2「数字唯一来源＝`aiqa_db.connect_ro` → `aiqa_engine.execute`」；「问答路径**不得**现场直读 Excel 母本」；决定 1「问答路径不再调用 `_qa._ledger_evidence`」。
- **代码实际**（都在 `_qa.build` 里，与 `_ledger_evidence` 平级）：
  1. `_qa.py:830-839`：`view is not None` 就给模型挂 5 件原生只读工具（`_qa_tools`/`_qa_executor`），模型可自主拉台账数字；这个 `view` 来自 738 行，**可能就是 `WorkbookView`（Excel）**，也可能是 `DataSource`（parquet 直读）。
  2. `_qa.py:435-438`：`_disc_rows` 直接 `open(out/<期次>/table2.csv)`，学科直答段（`_disc_segment`，476-525）的数字由此而来，指针写 `table2.csv#…`。
- **后果**：台账段只删 738-741 的话，这两条都还在；问数 sqlite 不是唯一来源，且第一条会读 Excel。ADR 的决定与验收（1、3）都没覆盖它们。

### E3（major）`metric_face` 那段：指标名单举错，且混了三个命名空间

- **ADR 原话**：「问数指标名带阿拉伯数字（`thr_1pct` / `thr_1permille` / `permille_rank` / `rank_pct` / `n_inst_1pct`），`metric_face.FACE` 的 `model` 列不覆盖问数独有指标（`metric_face.py:58-68`）」。
- **代码实际**：
  - `thr_1pct` / `thr_1permille` 不是 `facts.metric` 名，是 `report_table2` 的**列名**（`aiqa_engine.py:42-43`）；facts 侧叫 `threshold_1pct` / `threshold_1permille`，二者在 FACE 里**有** `model` 别名（`threshold` / `threshold_permille`，`metric_face.py:38-43`）。
  - 真正 `model:""` 的 5 个是 `rank` / `rank_pct` / `n_inst_1pct` / `avg_cites` / `permille_rank`（59-68）。ADR 漏了 `rank` 与 `avg_cites`，多列了两个已有别名的。
  - 附带发现（未核证到运行期，只核到字典来源）：`avg_cites`、`permille_rank` 不在 `dim_metric`——`aiqa_db.py:425` 只从 `flexible.datasource.METRICS` 建字典，实测库 `dim_metric` 13 个指标里没有这两个；它们却有 `ask` 别名（`metric_face.py:65-68`），执行时会以「不在白名单」被拒（`aiqa_engine.py:364-366`）。扩别名之前得先定这两项从哪张表来。

### E4（major）决定 8「`_plan` 无调用方」不成立

- **ADR 原话**：「`_plan` + `plan_examples.json`（票 03/04 的模型规划面）在一期后**无调用方** → 标 deprecated，二期删」。
- **代码实际**：`tools/verify_qa_plan.py:20` 顶层 `from ai import _plan`、`:31` 用 `_plan.rule_specs`（规划金标回测，EXIT 0/1 的工具）；`tests/` 里 12 处以上引 `_plan`。冻结后失去调用方的只是 **`_plan.plan`**（模型规划入口），模块与例子库仍被金标工具消费——按 ADR 二期删会打断这个工具，且 `plan_examples.json` 会变成孤儿文件而不是随模块一起退休。

### E5（major）`_view_for` 还有一个调用方，收口计划漏了

- **ADR 原话**：决定 2「`_qa._view_for` 的 `WorkbookView` 支路退场」；决定 8 只列「`_evidence.value_face` 仍被 `tools/qa_eval.py` 解期望值用」。
- **代码实际**：`tools/qa_eval.py:383` 直接调 `_qa._view_for`，`:385` 用它跑 `resolve_values`。WorkbookView 支路一退，无 parquet 期次的评测会静默变成 `view is None` → `resolved=[]`（不报错、只不再对值）。收口清单必须补这一项。

### E6（major）「加列 = 三处 aiqa_db + `_TABLE2_COLS` 一行」不足

- **ADR 原话**：决定 4「`thr_1permille_gap` 进 `compute.build_table2` → `table2.csv` → `aiqa_db`（建表/写入/列白名单三处）→ `_TABLE2_COLS` 加一行」。
- **代码实际**：
  - `aiqa_db` 三处准确（DDL `:101`、读取 `:254`、`INSERT` `:476`）。
  - `_TABLE2_COLS`（`aiqa_engine.py:40-45`）与 `_EXEC_COLS`（`:334-335`）**全仓无任何引用**（grep 只命中定义行）——加行不改变任何行为。
  - 真正的列门是 `_table2_join` 里硬编码的 SELECT（`:345-347`），不加上就取不出新列。
  - `render_row` 的 `table2` 分支（`:599-609`）只渲染 papers/total_cites/cnci/top_papers/rank_cn_change/permille_rank/prox_change，连 `thr_1pct`、`thr_1permille` 都不打印——新列要进答案就得改渲染。
  - 另有 11 列契约与 5 处登记面（见 §三-R3、R6），不在 ADR 的改动清单里。

### E7（minor）行号微差三处

- `queries.py:3` 的「唯一入口」实际在 **`:2`**（`:3` 是「红线落点：…」）。
- `aiqa_db.py:142` 是注释行（「问数留痕」），`qa_log` 表体在 **`:143`**；「唯一运行期可写表」的结论本身成立（`LOG_TABLE="qa_log"`:60、写口 `connect_rw`/`log_qa`）。
- `_qa.py:132-164` 只覆盖函数中段，函数体起于 **`:121`**；三个调用点都在范围内，按引用用途可接受，但严格说不是「台账段代码」的完整范围。

### E8（minor）两处措辞与代码不符

- **ADR**：「问数库的上游**全是**流水线产物」。**实际**：`build()` 还会读母本 xlsx 算 `ledger_sha256`（`aiqa_db.py:406`、`:497-498`）——只哈希不取值，但「全是产物」不精确。
- **ADR**：「`DataSource` 属**产线内部**：`build_aiqa_db` 的 ETL 与灵活报告第二产线」。**实际**：ETL 用 `pandas.read_parquet` 直读（`:215`、`:339`、`:368`），从不构造 `DataSource`；它只 import `flexible.datasource.METRICS`（`:422`）与 `_LONG_SPEC`（`:597`、`:616`）。`DataSource` 的产线用户只有灵活报告线。

## 三、ADR 未覆盖的风险

### R1（major）「不修订就是文档打架」——还漏了 5 处写同一回落

ADR 只点名票 01 的 spec 与 `queries.py`，实际另有：

- `.scratch/llm-arch/issues/01-引擎扩op.md:11-12`（done 票，「＝监测表直读回落适配器——parquet 缺席时用」）、`:20-22`（「已定：数据面 parquet 优先…缺席回落监测表 Workbook」，且写的路径是 `input/<期次>/监测表.xlsx`，与实际 `input/云大…动态检测表.xlsx` 也不一致）、`:30-31`；
- `src/flexible/datasource.py:8-10`、`:148-149`（`LedgerView` docstring 同样写「回落」）；
- `src/flexible/workbook.py:2-11`（「`LedgerView` 的**回落**实现（parquet 产物缺席时用）」）；
- `src/ai/_qa.py:26-27`（模块 docstring「监测表回落（`_view_for`）」）；
- `src/flexible/queries.py:22`（ADR 已列）。

不改这些，「问答侧取消回落」与模块文档直接矛盾——这正是 ADR 自己说的那种打架。

### R2（major）验收 1 的桩不可证伪，绿测两种结论都能过

- `_view_for` 自己吞异常：DataSource 支路 `except Exception: return None`（`:94-99`），WorkbookView 支路 `except Exception: return None`（`:111-115`）。把 `WorkbookView` 打成抛错 → 被吞成「视图缺席」，链路照常出答案，**不会炸**。
- `_aiqa_reply` 整体 `except Exception`（`_dialog.py:938-940`）→ 吐一句「这一轮没查成」，测试若只断「有回答」仍然绿。
- aiqa 侧今天根本不 import 这两个类（`_aiqa_reply` 只 import `aiqa_db`/`aiqa_engine`），桩在正确实现**前后**都打不响；`qa_direct=True` 时普通问数也不进 `_qa`。ADR 说「另跑一次不设桩的对照，证明该桩确实拦得住」——不设桩只能证明链路正常，不能证明桩会拦。
- 建议：改成计数断言（`_qa._view_for` 调用 0 次、`WorkbookView.__init__`/`DataSource.__init__` 0 次），并指明驱动问句（例「查一下 202607 那期」：不带指标、过不了 1034 的门，但会进 `_qa.build`）。

### R3（major）`table2.csv` 是「11 列 / 242 格」的书面口径，加第 12 列不是局部改动

- `tests/test_pipeline_smoke.py:51` 断言**精确列序** 11 列；
- `src/agent/audit.py:8`（242 格＝22×11）、`tools/verify_report_cells.py:133`（首列 + 10 数值列）；
- `server/workbench.py:61`（c1..c10 对应列序）、`src/fill_docx.py:59`、`src/backtest.py:72-83`、`tools/method_boundary.py:47-59`（列性质表，未登记列会被单列「未登记列」）；
- 上游说明 `src/run_pipeline.py:207`、`docs/操作手册（网站版）.md:65`、多份 `web/mockups/*`。
- 更便宜的路：`total_cites` 与 `thr_1permille` 都已在 `report_table2`，差距可在 `aiqa_db` 的 ETL 或引擎参数化 SQL 里派生（确定性、不过模型），`table2.csv` 一个字节不动。

### R4（minor）撤 `_SERIES_SPAN` 排除会掉一块台账段能力

台账段有 `span=recent`＝截至当期最后 6 列（`_qa.py:150-154`）；问数 `series` 只有 `period_max`（`aiqa_engine.py:367-371`），没有 N/窗口参数。撤掉排除后，「最近六期怎么变的」会被答成「全期序列 + 最新值」，与决定 3「对齐台账段今天的覆盖面，否则唯一入口＝能力倒退」冲突。决定 5 只把「N 档」给了模型面，执行面没有。

### R5（minor）旗舰「拉大/缩小」的符号与算法层没写死

`thr_1pct_gap` 有符号（`compute.py:105`），渲染先例是负值说「还差」、正值说「高出」（`_qa.py:504-517`）；而 `render_row` 声明「零计算」（`aiqa_engine.py:561`）。1‰ 差距对未进入学科是负值，「拉大/缩小」要先定「按 |差距| 变化」还是「按接近度变化」，以及由哪层算（引擎侧确定性比较，不是渲染器随手减）。ADR 验收 7 只写「出正确方向」。

### R6（minor）新算子 `column_series` 的登记面是 7 处，不是 1 处

现有算子要在 `_KINDS`（`:52-53`）、`execute` 分派（`:352-468`）、`_KIND_CN`（`:518-520`）、`describe_specs`（`:523-553`）、`render_row`（`:556-653`）、`suggest_chart`（`:673-714`）、`to_chart_data`（`:717-755`）各有一份。漏 `describe_specs`/`suggest_chart` 不会报错，只会把过程轨迹显示成 kind 原名、图型退 table。

## 四、建议改动清单

1. **决定 1 换落实点**：把「撤销 1040-1044」改成「关 `qa_direct` 门（1034-1039）→ 不再把问句提升成 `query`（1040-1044、1090）→ 服务器 `kind=="query"` 不再 `ai.run("qa")`（`server/routes/dialog.py:417`）」，并加一条用例：`qa_direct=False` 下「查一下化学的接近度」既不调模型也不进 `qa`。
2. **决定 2 补两条漏网**：`_qa_tools`/`_qa_executor`（`_qa.py:830-839`，`view` 可能就是 Excel）与 `_disc_rows`（`:435-438` 直读 `table2.csv`）；决定 1 的冻结要连工具环一起关。
3. **验收 1 换判据**：计数断言＋正控（旧行为下计数 >0）＋指定驱动问句；不要把「打成抛错」当判据，它会被 `_view_for`/`_aiqa_reply` 的 `except` 吞掉。
4. **重写 `metric_face` 那段**：真名单是 `rank`/`rank_pct`/`n_inst_1pct`/`avg_cites`/`permille_rank`；并先定 `avg_cites`/`permille_rank` 的数据面（现在不在 `dim_metric`，问数取不到）。
5. **收口计划补两项**：`tools/verify_qa_plan.py`（金标用 `_plan.rule_specs`）、`tools/qa_eval.py:383`（用 `_view_for`）；`_plan` 只把 `plan` 入口标 deprecated，模块与例子库的退休时间单独定。
6. **旗舰例子改走派生列**：`thr_1permille_gap` 在 `aiqa_db` ETL 或 SQL 里由 `total_cites - thr_1permille` 出，不动 `table2.csv`；若坚持进大表，把「11 列→12 列」契约、`test_pipeline_smoke.py:51`、`agent/audit.py`、`verify_report_cells.py`、`method_boundary.COLUMN_KIND` 一并写进改动清单。
7. **撤 `_SERIES_SPAN` 前先给 `series` 加窗口参数**（沿用 `span=recent` 的 6 期口径），否则保留反问，别用「能力倒退」换「入口唯一」。
8. **文档与行号同步**：补 R1 的 5 处回落说明；顺手修 `queries.py:3`→`:2`、`aiqa_db.py:142`→`:143`、`_qa.py:132-164`→`:121-164`。

> 未核证：`events` 表上游（台账《学科进入时间》/`wide/entered_1pct.parquet`）未逐期验证；`ai_calls` 新增 capability id 的写法未核（属未实现设计）。本次不改动被审文件。
