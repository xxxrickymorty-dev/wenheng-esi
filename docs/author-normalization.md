# 学者名归一化：调研与结论（只调研，未实现）

> 2026-10-22 · 结论先行：**现在不做**。清单里能拿到的只有「姓, 名/缩写 + 第一作者/通讯作者标记 + 学院」，
> 没有 ORCID / WOS ResearcherID / 工号这类能定人的东西；同姓同首字母的歧义在 202609 就有 29 组。
> 要做也只能做成「机器提候选 + 人逐条签认」的重量级人工活，而报告出版件并不需要学者粒度。

## 一、清单里到底能拿到什么

`《<期次>论文清单.xlsx》` 的「云大作者」列（每篇一行，202609 实测 291 行）：

| 能拿到 | 形态 | 202609 实测 |
|---|---|---|
| 作者姓名 | `Surname, Given` / `Surname, Initials`，第一段 | 88 个不同姓 / 205 种名写法 |
| 缩写 | 只有首字母或缩写（`Zhu, L`、`Dai, B. Z.`） | 12 行 |
| 身份标记 | `/通讯作者/`、`/第一作者/`、`/第一作者、通讯作者/`，或**没有** | 通讯作者 139、第一作者 104、无标记 143 |
| 是否「等」 | 名字后带「等」＝该篇还有别的作者（不列名） | 109 行 |
| 所属学院/机构 | 斜杠后最后一段（本仓已归一，见 `config/college_map.yaml`） | 23 个单元 |

拿不到：ORCID、ResearcherID、工号、作者顺序、每位作者的独立单位（清单只留**一个**云大作者）、
以及「等」后面那些人的名字。`WOS收录号` 只能定位**论文**，不能定位**人**。

## 二、风险有多大（都是实测，不是估计）

1. **同姓 + 同首字母 = 多个人（202609：29 组）**。例：
   - `Zhang, Y` → {Ya-Ping, Yixin, Yanqing, Yumin}（4 个人共用一个缩写键）
   - `Zhang, T` → {Tianwei, Tao}；`Zhu, L` → {Lei, L}
   - `Zhang, G` → {`G. S.`, `G. S`}（同一人两种写法，**连"是不是同一人"都要人判**）
   缩写与全名混用（12 行只有缩写）时，机器无法判断「`Zhu, L` 是不是 `Zhu, Lei`」。
2. **同姓跨学院（202609：31 个姓出现在 ≥2 个学院）**：`Zhang` 横跨 7 个单元、`Yang` 5 个。
   用「姓 + 学院」当键会把不同的人并成一个，用「姓」当键更糟。
3. **规模放大**：五期合计 1325 篇（`../文档/学院归属表（五期报告汇总·20260925）.json`）。
   逐期新增约 291 行；每行至少一次判断，撞键的还要翻原文核对。
4. **没有回归判据**：学院层有出版件第 7 页可以逐行对（本仓的做法），
   学者层**没有任何官方的"应有的名单"**——错了也验不出来。这违反本仓的验收口径
   （「报告数字对」而不是「断言全过」）。

## 三、成本估算

| 做法 | 一次性成本 | 每期增量 | 可靠性 |
|---|---|---|---|
| 纯人工建名单（按姓名+学院判） | 约 1325 行 × 10–15 秒 ≈ **4–5.5 小时**，含撞键复核再加 ~1 小时 | 约 291 行 ≈ **50–70 分钟** | 低（缩写与「等」无法复核） |
| 机器提候选 + 人签认（照学院那套分工） | 机器只能提出「同姓同首字母」的候选，29 组/期全部要人判 | 29 组 ≈ **10–15 分钟**，但判不了的仍要翻原文 | 中（能挡住明显误并，挡不住漏并） |
| 引入外部作者库（ORCID / WOS） | 需要馆员导出作者级数据；现有清单**没有**这一列 | 取决于导出方式 | 高，但超出「清单→报告」这条链的边界 |

## 四、结论

**不做**，理由三条：

1. **出版件不需要**：报告用到的是学院/机构粒度（学院统计表、学院贡献度饼图、概述段句），
   学者粒度没有对应槽位；做了也没有地方印。
2. **数据不够定人**：没有权威 ID，缩写在 12 行里就是唯一信息；29 组撞键要人工翻论文原文，
   「机器建议」在这里不可能可靠——而按红线我们又不能把模型放进数据路径。
3. **验不出来**：学院层能对出版件逐行核，学者层没有金标准，做出来只能"看起来对"。

## 五、如果以后真要做（最小路径，供决策）

1. 先让馆员在清单里**加一列**：`ORCID`（或 WOS ResearcherID）。有这一列，归一化就退化成
   `ID → 姓名` 的字典，机器可判、可复核；
2. 拿到 ID 之前只做**同篇内**的去重（同一篇里同名只算一次），不做跨篇合并；
3. 若要跨篇合并，照学院这条链的分工来：`config/author_map.yaml`（`ID/写法 → 规范名` + 确认人/时间/依据）
   + `out/<期次>/author_review.md`（待签认）+ 人签认，**绝不**在运行期让模型猜；
4. 验收判据必须先立起来（例如「某位通讯作者在 X 期的论文数」与人工清点一致），
   否则不做——没有判据的自动化，只是把错埋得更深。
