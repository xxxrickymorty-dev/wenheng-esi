## 问题

全站设计审查（两路子代理逐屏、带行号证据）确认六类问题（详见附录）：

1. **期次上下文**（最系统性）：当前期次不进 URL，刷新/复制链接/后退即丢；全站 5 处可改期次且互不同步；生成台会显示别期任务；一屏并列五个期次名。
2. **危险动作无护栏**：撤回签单、重跑、重出、上传覆盖、放弃修改全是"一点即生效"，零二次确认；无回滚入口；承诺的「取消任务」不存在。
3. **术语与状态词漂移**：一个动作五种说法；状态词四套（后端十态 / 前端 wb.ts / 各页自写 / 审批三态）；**导师明确禁用「数字图书馆」**。
4. **空态/错态死胡同**：空态只有解释没有动作；404 不给"去生成"；403 的"再试一次"原地复读；台账报错是给后端排障的话术。
5. **交互一致性**：预测台路线控件三套、可能"改 A 存 B"；标存疑是隐性 toggle；知悉勾选不拦签单；运行档案用签发色表示任务完成。
6. **可达性/密度**：首屏 640 字（目标 ≤180）；字号 <13.5px 多处；点击区无 44px 规则；技术术语与调试尾巴直出面客；窄屏问题；陈列馆单向门。

## 方案

1. **期次唯一真相 = URL**：`?period=` 读写模块 + 顶栏「期次章」；页面内所有期次入口一律写 URL（不再各自为政）。
2. **导航分组**：`生成台→报告→审核台 ｜ 台账·分析台·预测台 ｜ 陈列馆`（组间分隔；陈列馆短标签保留，页面品牌=云南大学图书馆）。
3. **危险动作护栏**：行内二次确认（按钮原地变「确认…？」，3 秒归还）；重跑/重出给「回滚到上一版」（重跑按钮旁 + 运行档案）。
4. **术语表执行 + 自动检查**：界面文案只用 `CONTEXT.md` 词表；黑名单词由 `check_web_app.py` 断言。
5. **空态/错态模板**：空态＝一句话＋一个下一步动作；错态＝缺什么＋怎么补＋有效重试；禁"只有解释没有动作"。
6. **信息减负四屏**（生成台→运行档案→预测台→审核台/报告）：四数字上限（hint≤24/导语≤60/首屏≤180/说明全站一份）＋就地折叠＋统一 ⓘ；每屏先静态稿后 React。
7. **图书馆侧**：全站改名（数字图书馆→云南大学图书馆）＋陈列馆加「回工作区」（管理员可见）。

## 用户故事

- 作为馆员：从报告页点「生成台」回到的是**同一期**；刷新不掉期；一眼看到"我现在该做什么"。
- 作为馆员：重跑前会被问一次；误重跑后能一键滚回上一版。
- 作为馆员：每个空页都告诉我下一步在哪；报错告诉我缺什么、怎么补。
- 作为评委：10 秒内答出"这页让我做什么"；问到"数字哪来的"3 秒能打开 ⓘ。
- 作为管理员：从陈列馆能走回工作区，不迷路。

## 实现决策

- 期次模块 `src/lib/period.ts`：`readPeriod()` / `applyPeriod()`（`history.replaceState`）/ 缺省=最新期；UI 用 `usePeriod()` 薄皮。
- 状态与术语模块：`src/lib/status.ts`（十态→话术唯一映射）、`src/lib/terms.ts`（词表常量）、`src/lib/banned.ts`（黑名单词表，供 UI 检查与 e2e 共用）。
- `ConfirmButton`：行内二次确认（3 秒超时归还；Enter/Space 均可触发）。
- 状态徽标统一为一个组件（`<StatusPill>`），运行档案不得借用签发色。
- spec/票落点：`docs/agents/issue-tracker.md`；前端测试框架：ADR-0003（vitest，纯逻辑）。
