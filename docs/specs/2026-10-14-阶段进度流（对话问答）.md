# spec：阶段进度流（对话问答）（2026-10-14）

- **状态**：rick 已定（2026-10-14「再做阶段进度流」；先文档后代码）→ ready-for-agent
- **票**：`.scratch/duihua-qianmen/issues/12-阶段进度流.md`
- **先例**：灵活报告流式（契约 #21③：NDJSON、真实节点、不造假进度）

## 目标

问答/对话的模型轮要等 10–60 秒，界面全程无信息。做**阶段进度流**：把"正在做什么"实时播出来，
**不播正文文字**——数字必须先过「数字盾」（核过来源）才能展示，边生成边出字会漏出未核数字。
终答仍整段到（走既有 `payload` 形状，前端渲染逻辑不变）。

## 事件模型（NDJSON，一行一事件）

`POST /api/dialog/turn/stream`（新；请求体与 #33 完全一致）：

```
{"event":"stage","stage":"理解","text":"正在理解这句话…"}
{"event":"stage","stage":"查数","text":"正在查台账…"}
{"event":"stage","stage":"model:qa-plan","text":"正在规划查哪些数…"}
{"event":"stage","stage":"model:qa","text":"正在写答案…"}
{"event":"done","payload":{…与 #33 响应同形状…}}
```

- 失败 → `{"event":"error","error":"…"}`（不抛断流）；
- 规则模式/无模型：只有 `理解 → 查数 → done`（**如实，不演**）。

## 挂点（真实节点，不造假）

1. **服务器编排点**（`_dialog_turn_impl`）：调 dialog 前发「理解」；查数据意图调 qa 前发「查数」；
2. **模型调用点**（`_attempt.attempt`）：模型真被调用时才发 `model:<ability>`
   （`qa-plan`＝规划、`qa`＝写答案、`polish`＝润色…）——规则模式不发（不许演）。

## 边界

- **不流正文**（数字盾前提）；不改 `#33` 响应形状；不动会话/留痕/数据路径；
- 前端：**先出静态稿**（`web/mockups/对话前门-进度流.html`，单文件零依赖）→ rick 审 → 再动 React；
- 兼容：老前端照旧用 `#33` 同步口，互不影响；流口出错时前端应回退同步口（React 接线时实现）。

## 测试决策

- ai 层：`ai.using(progress=收集器)` → 模型轮收集到 `model:qa-plan`/`model:qa`；规则轮**没有** `model:*`；
- 服务器：流口 NDJSON 逐行形状（stage×N → done.payload 与同步口同键）；错误路径出 `error` 事件；
- e2e（可选）：登录后 POST 流口，首行可解析、末行 done。
