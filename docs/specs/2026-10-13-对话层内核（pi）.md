## 背景与决定（rick 2026-10-13）

对话前门目前是纯规则（`modeled=False`），「最新的 / 指代」类问法靠规则补丁（票 10 只补了「最新」）。
rick 定：**把 pi 移入对话层当内核**——工具＝现有引擎、输出过盾、不进数据路径；
框架能帮的是「对话记忆 / 多步」那层体验，命根子（台账 / 盾 / 证据 / 期次 / 离线 / 留痕）仍自研。

## 架构

```
对话层（内核可缺席）
  规则 parse（确定性，永远第一道）
    ├─ 命中 → 原路（现有行为逐字保持）
    └─ 未命中且模型可用 → pi 内核补槽（只出槽位，零数字）
          工具（只读、零台账数值）：list_periods / scan_inventory / product_status
          输出校验：只取 {period,intent}（围栏/白话容忍；其余键带数字即拒）；period∈列表、intent 白名单归一；拒 → 回退规则
  离线（无 key / PROFILE=demo / qa 关）→ 不启内核，纯规则（演示站完整可用）
```

- **模块**：`src/ai/_dialog_kernel.py`（模型出口仍只有 `src/ai` 一处）；
- **内核**：pi agent loop（Python 移植）——StreamFn 自供（真实＝OpenAI 兼容单发、复用 `_brain` 姿势；
  测试＝Scripted）；服务端仍无状态（历史随请求带上；pi 的会话树 / 压缩本阶段不用）；
- **工具白名单（阶段一，零台账数值）**：`list_periods`（payload.periods）/ `scan_inventory`
  （既有盘点注入，只报件在不在）/ `product_status`（有无产物）；qa 引擎**仍由服务器按意图路由**
  （契约 #33 不变），不进内核工具面；
- **留痕**：每轮一条 `ai_calls`（capability=dialog，mode=model|rule|fallback 如实；
  内核轮的 backend / fallback 原因码 / egress / elapsed 如实入记录；`Answer.mode` 恒 rule——
  正文始终规则拼装，徽标不冒充模型版）；
- **开关**：跟随 qa 能力开关（禁新旋钮，wayfinder 票 11 裁决）。

## 触发点与回落规则（票 03 定稿口径）

- **触发点（唯一）**：`_dialog.build` 里当且仅当「句内没有期次（`case=no_period`，即显式期次 /
  出稿月纠正 / 「最新的」都不算）＋ 有对话上文 ＋ 规则未命中（非短应诺）」且内核可用时，
  调 `_dialog_kernel.assist()`。规则命中（含槽位带过轮、短应诺）一律原路，不问内核。
- **补槽生效**：内核给非空期次 → 按它落期次（覆盖旧槽位），后续按既有意图路由走
  （报告 → 盘点；查数据 → 服务器调 qa；推进 → 目标期次用补出的）；给空 → 维持原样。
- **回落**：内核失败 / 超时（总预算＝2×`WENHENG_AI_TIMEOUT`）/ 坏输出（非 JSON、白名单外键、
  期次不在 `payload.periods`、出现其他数字）/ 离线（无 key、`PROFILE=demo`、qa 关）→
  **不改任何东西**，一切按原规则（含「查最新的」候选）。
- **测试面**：`ai.using(dialog_kernel=<StreamFn>)` 注入脚本流（Scripted 零网络）；
  既有 `tests/test_ai_dialog.py` 全过且内核缺席时行为逐字不变（红线）。

## spike 结论（票 01，2026-10-13）

- **候选对比**：`pi-agent-core` 0.1.1（PyPI，Huvinesh Rajendran，MIT，Alpha、单维护者，~22KB；
  依赖仅 pydantic≥2 / httpx，是 TS pi-mono 的忠实移植，StreamFn 自供）
  vs `yuramalna/pi-python`（`pi-llm-agent` 0.1.4 + `pi-llm`：依赖 openai SDK / jsonschema /
  json-repair，HTTP 层随包，体量大、模型客户端是第二套）。
- **选定**：`pi-agent-core` 0.1.1——StreamFn 接缝干净（真实＝自研 OpenAI 兼容单发；
  测试＝Scripted），依赖面最小（pydantic 主 venv 已有），loop 与事件面够用。
- **内置方式**：**vendor 快照**（不动 pyproject.toml / uv.lock / .venv）：
  `src/_vendor/pi_agent_core/` 收 `agent.py` / `agent_loop.py` / `types.py`（与 wheel 逐字节一致，
  sha256 已对 wheel RECORD 校验）+ 精简版 `__init__.py`（去 `proxy` / `anthropic` 两个需要
  httpx / anthropic 的模块）；来源 / 版本 / 许可 / 哈希 / 更新姿势见 `src/_vendor/README.md`。
- **验证（spike 脚本，临时环境，零网络）**：脚本化 StreamFn 跑通「工具调用 → 终答」多步 loop
  （返回槽位 JSON）；`asyncio.run` 在工作线程内与 FastAPI 主循环共存（`run_in_threadpool` 同款）；
  `asyncio.wait_for` 超时路径可达；真实流的错误码映射与 `_brain` 同源（unreachable 冒烟）。
- **async 接法**：内核在 `ai.run`（同步阻塞）里用
  `asyncio.run(asyncio.wait_for(loop, timeout=2×WENHENG_AI_TIMEOUT))`；调用方保持
  「同步阻塞、FastAPI 侧 to_thread」既有契约；同线程已有事件循环时 `asyncio.run` 抛
  RuntimeError → 按内核失败回落（不拖垮对话）。
- **不做**：真实模型联网调用（留给 04 验收）；`server/app.py` 零改动。

## 风险与退路

- pi-agent-core 是社区移植（PyPI 0.1.1，Alpha、单维护者）→ **已 vendor 快照入库**（spike 定）；
  质量不足 → 备选 `yuramalna/pi-python`，或**同一接口换自研薄循环**（接口不变、实现可换）；
- async 与 FastAPI 的接法已在 spike 验证（见上）；
- 部署打包需带 `src/_vendor/`（票 04 热更评估时核）。

## 范围外

- 数据路径的任何模型参与；服务端会话存储；自由上下文长期记忆（ADR-0006 维持）。
