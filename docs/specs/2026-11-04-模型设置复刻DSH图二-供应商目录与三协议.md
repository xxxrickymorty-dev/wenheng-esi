## 病例与意图

- 2026-11-03 落地的供应商式配置是「一条配置＝一个型号」：
  云大网关有 34 个型号，每用一个就得加一条，重复填地址与 key；
- 协议字段只存 `openai` 一种，后端不实现第二种——界面只有假选项；
- 没法从网关拉型号清单（探活只回数量不回清单），型号全靠手抄。

## 契约（对照 DSH 图二/图三）

### 后端（`src/ai/_models.py` v2 + `src/ai/_brain.py` 三协议）

- models.json **schema 2**：`{active:{provider,model}, providers:[{id,label,
  base_url,key,protocol,headers,note,added,models:[…]}]}`；
  schema 1 旧清单读入自动迁移（每条旧记录→单型号供应商），落盘即 schema 2；
- **当前模型＝「哪条供应商＋目录里哪个型号」**（原来只有条目 id）；
- 一条供应商＝网关接入（地址/key/协议/自定义头）＋**模型目录**
  （挑过的型号子集，≤64 条，去重保序）；
- `upsert`/`set_active`/`remove` 全部改供应商口径；当前型号被移出目录
  ＝回目录第一个；目录清空/没 key＝不再当前；
- 新口 `fetch_models`（拉网关 `/models` 型号 id 清单）＋路由
  `POST /api/models/list-remote`（admin）；探活改走同一份取清单实现；
- `_brain`：抽 `_HTTPBrain` 公共骨架（构造/请求头合并/发包/错误码映射/
  外发预算），`OpenAIBrain`（Chat Completions）收进去**单发行为逐字不变**；
  新增 `ResponsesBrain`（`/responses`：instructions/input_text/output_text/
  function_call/function_call_output，status:incomplete→finish=length）与
  `AnthropicBrain`（`/messages`：x-api-key＋anthropic-version、max_tokens 必填、
  消息严格交替、tool_result 回传、input_schema）；分派只走 `make_brain`；
- `_config.cloud_config` 透传清单条目的 `protocol`；`build_brain`/
  `_dialog_kernel`/`_writing` 三个构造点全走 `make_brain`；
- `tools/qa_eval.py`：`--model <id>` 改 `--provider <id> [--model <型号>]`。

### 前端（`web/src/dialog/ModelPanel.tsx` + `api-models.ts`）

- 供应商卡片：label＋当前/部署/未配齐徽标＋当前型号＋地址＋key 掩码＋
  「N 个型号」；动作 用这个/测一下/改/删（语义不变）；
- 表单照图二字段序：**API 密钥（留空使用已保存凭据）/ 显示名称 / API 地址 /
  API 协议（三选，图三）/ 模型目录 / Headers（可选）/ 备注**；
- **模型目录**（图二形制）：已选型号成 chip（× 删除）＋手动加一行＋
  「获取可用模型」（拉网关清单→点选加进目录）＋「恢复默认模型」
  （地址匹配预置时出现，目录回预置）；
- 模型菜单（输入框左下）：平铺每条配齐供应商的目录型号，
  左型号右供应商名；`.env` 部署配置行照旧。
