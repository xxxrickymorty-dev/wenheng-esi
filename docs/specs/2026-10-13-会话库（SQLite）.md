# spec：会话库（SQLite）——服务端会话持久化（2026-10-13）

- **状态**：rick 已点头（2026-10-13：服务端会话用 SQLite）→ ready-for-agent
- **票**：`.scratch/duihua-qianmen/issues/11-会话持久化（SQLite）.md`
- **先例**：`web/UX-对话前门.md` P1「槽位/对话持久化：进 URL？进服务端？」——本 spec 落「进服务端」
- **边界（写死）**：只存会话（对话文本/槽位/时间/用户）；**不存任何台账数值、不进数据路径**；
  不落 `input/`、`数据与复现/`、`out/<期次>/`；路径唯一口径在 `src/session_store.py`。

## 决定

1. **服务端会话存储**：SQLite 单文件 `out/_sessions/sessions.sqlite`（stdlib、原子、备份＝复制）；
   替代原「localStorage＋URL」方案的服务端半边。
2. **URL 带会话 id**：`/app/dialog/?s=<id>`——刷新/换设备带 URL 即恢复；首轮无 id → 服务器建。
3. **绑定用户**：会话归创建者（admin/operator/demo），他人读不到；按用户保留最近 20 个（默认）。
4. **历史口径不变**：`history` 载荷照旧（服务端从会话库取，截断口径与现状一致）；对话层仍不做
   自由上下文记忆（ADR-0006）——会话库只存「已经发生过的对话」本身。

## 接口

- `src/session_store.py`（函数一律注入 `db_path`，测试用 tmp）：
  `create(user) -> id`、`append(id, who, text)`、`load(id, user)`、`save_slots(id, slots)`、
  `list_sessions(user)`、`drop(id, user)`；`schema_version` 入 meta。
- 服务器（`server/app.py`，只动 dialog 段）：
  - `POST /api/dialog/turn` 增 `session`（可省）：有 → 历史从库读、回合追加进库；无 → 建新会话；
    响应增 `session_id`；
  - `GET /api/dialog/session/{id}` → `{id, slots, turns:[{who,text,ts}]}`（仅 owner；404/403 与既有口径一致）。
- 前端（`web/src/dialog/`）：URL 参数 `s` 读写；带 `s` 进页 → 拉会话渲染；每轮回写 id；
  「新对话」清 `s` 与本地状态。

## 验证

- 单测（tmp）：建/追/读/清/用户隔离/上限/形状非法；
- API 测试：注入 tmp 库；turn 无 session 建新、带 session 续写；GET 权限；
- 前端 vitest：URL 参数读写纯函数；
- e2e：`turn → session_id → GET 回读` 往返（在 e2e_check 对话段后加）。

## 范围外

- 跨会话检索/摘要/压缩；pi 会话树（内核后议）；localStorage 方案（不做）；旧数据迁移（不需要）。
