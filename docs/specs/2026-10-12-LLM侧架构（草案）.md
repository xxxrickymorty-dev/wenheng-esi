## 缘起（2026-10-12 rick 两问）

1. 截图死循环（「物理学的 1% 阈值是多少」→「最近一期的」→ 复读「查哪一期？」）：
   那是**对话前门**的规则缺口，另案修（前门仍 `modeled=False` 不动）。
2. 「能不能借鉴 RAG，拆问题去检索召回……LLM 思考后写查询语句去查，查到后总结输出」——
   典型问法："某个数据报告里没有、是台账某一期某个数据"。
   本文回答的是后者：**问数引擎的内部架构**。

## 问题

- `_qa.py` 的台账证据 = **手写关键词段**：固定指标表、固定"近六期"——
  加一种问法就要改一处代码；"数字到格"靠按值猜格（`register` 里 `len(paths)==1` 才到格，
  撞值降行级）。
- 规划与取数耦在一个 600 行文件里；`flexible/queries.py` 已证明"受限查询＋来源链"是正确形态，
  但只有灵活报表一个消费者——第二个消费者（问文衡）该接上。

## 用户故事

1. 作为馆员，我想问"某学科某期某指标"，即使报告里没有、台账里有，也能答上来、
   点数字能看见台账那一格。
2. 作为馆员，我想让"答不上来的问法"变成一次可点的选择，而不是复读同一句话（前门侧）；
   引擎侧：模型缺席时答案不缺席（规则兜底同形）。
3. 作为维护者，我想让"新增一种问法"只动一处（引擎加一个 op＋渲染），
   而不是在每个能力口里再写一段。
4. 作为维护者，我想让模型永远碰不到数值本身——它只选字段（规划轮）、只写措辞（写作轮）。
5. 作为评审，我想在运行档案里看见"这次查了哪些数、规划来自模型还是规则"（票 04：记录先行、界面列后）。

## 方案

### 一条流水线

```
前门认期 → 规划器认问 → 引擎取值 → 写手成文
（规则·已定）  （模型/规则）  （确定性·只读）  （现有 _core/盾不动）
```

### 不变量（四条，任何实现不得违反）

1. **模型的输出类型里没有数值**：规划轮输出 = 白名单名字（零数字 token）；
   写作轮输出 = 占位正文（数字已变 `[[n]]`）。**期次不走模型**——沿用确定性解析
   （保"期次猜错＝整期返工"红线）。
2. **值只从一条缝进来**：引擎（台账/产物只读视图）→ 带来源链的 `Result`；
   计划面（名字）与值面（数值）之间没有第三条路。
3. **离线兜底＝同端口的另一个适配器**（演示站规则锁），不是代码分支。
4. 每次能力调用一条留痕；外发面最小（复用 `Brief` 预算）。

### 模块与接口

| 模块 | 接口（调用方要学的全部） | 实现隐藏什么 | 缝与适配器 |
|---|---|---|---|
| **取数引擎**（深化 `flexible/queries.py`） | `execute(view, spec) -> Result` | 白名单校验、期次窗口、派生计算（比值/差/排名）、中性句渲染、来源链拼装 | **LedgerView**：Parquet（产物）／监测表 Workbook（直读）——两适配器＝真缝 |
| **取数规划器**（新 `src/ai/_plan.py`） | `plan(question, *, schema, history) -> QueryPlan` | 提示组装、JSON 围栏解析、规格清洗、回退政策 | **RulePlanner / ModelPlanner**——两适配器＝真缝；模型访问复用 `_attempt`（不改边界） |
| **证据装配**（新 `src/ai/_evidence.py`） | `assemble(results, question, *, limit) -> Evidence` | 排序（命中优先）、去重、截断预算、逐 op 中性句渲染 | 无（进程内）——不设缝，直接测接口 |
| **qa 编排**（`_qa.build` 深化） | `build(root, period, payload) -> RuleDraft`（**不变**） | ~30 行胶水：plan → execute → assemble → 组稿 | 无 |

```
QueryPlan = {"specs": [spec...], "origin": "model"|"rule", "note": str}
spec      = {"op": "series|at|compare|delta|events", "metric": <白名单>,
             "discs": [<名字>], "span": "all|recent|slot"}
Result    = {"op", "spec", "values": [{"value", "chain"}], "text", "cells": [(数字串, 指针)]}
Evidence  = {"chunks": [(key, text)], "cells": [(数字串, 指针)], "rule_keys": [key]}
```

### 删除测试

- 删引擎 → flexible 与 qa 各长一份取数 → 留；
- 删规划器 → 编译/清洗/回退散进每个要查数的能力口 → 留；
- 删证据装配 → 回到 600 行内联装配 → 留。
- qa 编排很薄是对的——它只是能力适配器，薄正好证明别的东西都深。

## 实现决策

1. **两种校验律，同一个 `_attempt`**：写作轮过数字盾（引用已注册标记、拒游离数字）；
   规划轮过"零数字＋白名单"（`anchored=False` 既有机制；越权键 / 带数字 → 整份回退 rule）。
   边界不改——`flexible/planner.py::_brain_plan` 已是先例。
2. **规划面词汇零数字**：含数字的规范键给**无数字别名**（如 `proximity_1pct` → 规划面 `proximity`；
   `threshold_1permille` → `threshold_permille`），别名表在引擎侧一处维护——
   防盾占位往返的碎边界。
3. **期次不进模型**：期次来自前门确定性解析（slot）或 `span` 枚举
   （`all` 全部有数据期 / `recent` 近 6 期（沿用台账问答 v1 口径）/ `slot` 对话期次，仅单期 op 用）。
   规划输出出现任何数字 → 拒。
4. **规格双道校验**：规划器对模型清洗一道；引擎再校验一道（`QueryError`，防御纵深）。
5. **精确指针**：引擎知道每个值的 chain，`Evidence.cells` 直接给
   `(数字串 → 台账#表/学科/期次)`；替换"按值猜格"（撞值降行级的模糊注册退休）。
   UI 指针形态（`kind=ledger_cell`）不变。
6. **结果先过编号才能进模型**：任何进 `Brief.evidence` 的文本必须先经 `NumberedText`
   （handoff 教训：上文不过盾，模型一复述数字就被判"游离"）。
7. **对外契约不变**：`/api/dialog/turn` 查数据轮、`Answer` 字段面、`build` 接口均不变；
   唯一契约触碰＝票 04 的记录 `plan` 字段（已定：记录先行、界面列后）。

## 测试决策

- **接口即测试面**：planner（ScriptedBrain 吐 JSON / 坏 JSON / 越权 / 带数字回退 / 零外发数字）；
  引擎（tmp 视图 / 未知即拒 / 逐值带链）；证据装配（Result 假件 → cells 精确到格）。
- **行为保持**：02 票换内核后，qa 现有全例必须原样过（这是判据，不是愿望）。
- **替换不叠加**：`_ledger_segments` / `_disc_segment` 的存量单测在新接口测试到位后删除。
- **金标问题集**：rick 实问沉淀（问句 → 期望 spec / 期望格），回测脚本随 04 票。

## 范围外

- 对话前门（期次/意图解析）不动；「最近一期」等前门修复另案。
- 自由 SQL / 代码生成；外部框架（vanna / DB-GPT 等）整装引入。
- 向量检索 / 嵌入（例子库起步关键词检索；加缝须等第二个检索器出现）。
- 写操作工具（模型永不触发写）。
- 图书馆侧语料与脱敏（wayfinder 既有范围）。

## 已定（2026-10-12，rick 授权由 agent 定）

1. **数据面：parquet 优先**。任意一期目录的 `ledger_long.parquet` 含**全期轴**
   （实测 `out/202607`：201903–202609，49 期 × 9 指标 × 22 学科）→ 演示站一份产物即全史可查；
   parquet 缺席（无流水线产物的环境/期次）回落监测表 Workbook（`input/<期次>/监测表.xlsx`，现行为）。
   ⚠ 注：演示站"问到早期次"还受服务器按期产物门（`resolve_period_dir`）影响——那是另一层
   策略，不在本票集。
2. **留痕：记录先行、界面列后**。票 04 先给记录加可选 `plan` 字段（向前兼容，旧读者忽略）；
   运行档案界面展示另出静态稿、rick 审后再动 React（`web/AGENTS.md` 铁律）。
3. **开关：跟随 qa 能力开关**，不新增旋钮（沿用 wayfinder 票 11「禁旋钮」裁决）；
   模型有无仍由部署配置决定（演示站规则锁照旧）。
4. **不做 design-it-twice**：`flexible/planner.py` 先例已把规划器接口压实；
   票 02 的"行为保持"验收本身就是接口合理性的检验；有异议再补跑。
