# spec：前门修复（二）——「最新」期次与复读兜底（2026-10-13）

- **状态**：rick 已点头（2026-10-13 计划 Stage 1）→ ready-for-agent
- **票**：`.scratch/duihua-qianmen/issues/10-最新期次与复读兜底.md`
- **先例**：`docs/specs/2026-10-10-对话前门.md`（§7 修订注记）；`docs/adr/0006`（对话只做指挥、不产数字）

## 问题（rick 截图实问）

「查一下化学的接近度」→ 反问「查哪一期？…」→「最新的」→ **复读同一句**（死循环）。

根因两条：

1. `parse()` 只认显式期次/月份（202605 / 2026年9月 / 9月），**不认「最新的 / 最近一期」**；
2. 无期次的查数据轮，反问话术恒同一句、`actions` 恒空——复说、点选都出不去。

## 方案

1. **解析「最新」**（`_dialog.parse`）：新增 case `latest`。正则只认「最新（的/一期/那期/＋名词）」与
   「最近（一期/那期/的那期/的）」；**不碰**「最近六期 / 最近几期 / 最新的几期」——那是序列问法，
   走 qa 的多期口径（负例进测试）。零数字、不猜。
2. **最近有效期次（单一口径）**：`taskview.known_periods()`＝**母本有效期次 ∪ 出过稿的产物目录**
   （凭证 `red_slots.json`，与服务器 `resolve_period_dir` 同一判据），降序。**取数在途、只记过对话的目录不算**
   （没数据，不算一期）——与「本期任务」（`taskview.scan`，含在途）的差别仅此一处：
   那边回答「任务走到哪」，这边回答「哪一期有数可查」。服务端把列表注入 `payload["periods"]`；
   `build()` 里 `latest` → `periods[0]` → 落成显式期次，两条意图路（报告 / 查数据）照旧。
   - 没注入/空列表 → 不猜：如实说「看不到期次列表」。
   - 若最近有效期次暂无产物：服务器照旧给「先出稿」提示——不猜、不换期。
3. **复读兜底**（`_query_reply`）：无期次的查数据反问不再裸复读——知道最近期次就写明
   「最近有效期次是 X（数据截至 Y-M）」，并给 `send` 候选「查最新的」（点击＝发回一句话，走正常一轮）。
   候选按钮**复用既有 `send` 动作渲染（零前端新件）**。
4. **不表态的「最新」**：`latest` 解析到但既无意图/查字样、又无上文 → `unclear`（做 X 的报告 / 查 X 的数据），
   与显式期次同款（不猜）；有上文 → 按追问走 `query`（2026-10-12 机制）——**截图序列由此出循环**。

## 契约（#33）

- 请求增 `periods: [六位期次…]`（服务端注入、降序；缺省＝空，旧调用方不受影响）；
- `case` 增 `"latest"`（解析中间态；落槽位前已解析成 `period`）；
- `actions` 无新增 kind（复用 `send`）。

## 测试决策

- **S1**（`test_ai_dialog`）：`最新的`（带上文）→ 落 202609 且 kind=query、不再复读；`查最新一期…` 带期次；
  `做最新的报告` 走报告路；`最新的`（无上文）→ unclear 两出路；无 periods → 如实说不猜；
  负例「最近六期 / 最近几期 / 最新的几期」不进 `latest`；反问含最近期次 + 候选「查最新的」。
- **S2**（`test_api_dialog`）：服务器注入 periods → 「最新的」落槽位；payload 形状含 `periods`（测试默认不读真台账）。
- **taskview**：`known_periods` 降序并集 + 空集。
- 端到端：e2e dialog 段照旧；手测复放截图序列。
