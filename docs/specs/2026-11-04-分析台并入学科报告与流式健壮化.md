# spec：学科报告并入分析台＋出稿流式健壮化

- **状态**：设计定稿（2026-11-04，rick 口谕：分析台与学科分析本是一物——学科分析的出报告
  功能放进分析台即可；并问「出报告一直卡住，为什么」）。

## 卡住诊断（已取证）

- **管线没病**：今晨 08:09–08:17 一次 write 模式生成完整跑完（47 次 polish 模型调用、
  8 分钟），产物全套落盘（flex_meta/report.html 等 08:14/08:17）——那就是 rick 点的
  经济与商业。
- **慢的来源**：写作位部署后，`report.py` `_mode_for` 只要润色位可用就走逐段 AI 润色
  （polish=None 自动档）——生成从「同步几秒」变成 **8 分钟/47 次调用**，UI 只有一行
  进度，观感＝卡住。
- **卡死的机制**：流式事件没有到达浏览器（后端在出事件＋本机传输实验逐条正常
  ＝同款中间件栈 1s×6 chunk 逐条到达；连接中断不排除——无 --reload，具体断因
  在客户端链路，无法在本机取证），而**前端对「流断了/无事件」零兜底**：fetch 无超时、
  流终止无终态事件时不报错 → 卡面永久「规划中…」。

## 契约（三票）

### 票 1 合并：学科报告进分析台（`AnalysisPage.tsx` + `SideRail.tsx` + `App.tsx`）

- 卡片网格（DisciplinePage 现实现整体迁入）成为分析台的一个区（**「学科报告」**），
  位置：分析台页头之后既有内容之前（subagent 看 AnalysisPage 结构定）；
- `SIDE_NAV` 删 discipline 项（SIDE_NAV 注释同步改真）；`App.tsx` 删 `view==='discipline'`
  分支与 DisciplinePage 路由；`DisciplinePage.tsx`/`discipline.css` 退役——组件与样式
  迁到分析台可复用位置（如 `web/src/discipline/` 或并入 AnalysisPage），测试同步迁移；
- me/period 传参不变；「打开最近一份」链保留在区头。

### 票 2 流式健壮化（`DisciplinePage 控制器` + `api-flexible.ts` + `src/flexible/report.py`）

- **后端心跳**：`generate_stream` 的 `q.get()` 改 `q.get(timeout=10)`，超时即
  `yield {"event":"ping"}`（真实事件照旧优先）；`FlexStreamEvent` 增 ping 类型。
- **前端**：`AbortController`＋**无事件超时 90s**（ping 也算事件，重置计时）；
  流终止但未收到 `done/error/stopped` → 视为连接中断：卡面显式报「连接中断——报告可能
  已在后台完成，点『打开最近一份』查看」并解除 busy；error/中断后自动轮询一次
  `getFlexible` 刷新最近稿状态。
- **时长预告**：`getFlexible().write.available` 为真时，区头注一句「写作位开启：出稿含
  逐段润色，需数分钟」（零数字面不涉及——这句无数字）。

### 票 3 文案与回归

- 卡面进度三态文案核对（规划中…/第 N 节…/收尾…）；测试迁移改造
  （DisciplinePage.test → 分析台挂载下的组件测试，用例语义不变）；
- 全量：`npx vitest run` 全绿＋`npm run build` dist 入库＋`uv run ruff check .`；
- UI 自查四点：导航无学科分析项、分析台内网格可用、无事件超时与中断提示正确、
  ping 不渲染但重置计时。
