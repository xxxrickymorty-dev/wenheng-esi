## 一、验收判据（本页自己的尺子）

1. **60 秒四问**：这是什么 / 解决什么 / 凭什么信 / 下一步去哪——不用滚动到底就能答。
2. 没有内容的过场屏消失（原建筑页的「进入阅览室」按钮由滚动替代）。
3. 动效服务于叙事（镜头移动＝空间旅程），不做装饰性乱动。
4. 降级可用：无 WebGL / 关动效 / reduced-motion 时，本页退化为可读文档 + 翻书仍可用。
5. 信息减负纪律不破：一屏一义、每屏主动作 ≤1、数字全部真实可溯源。

## 七、技术落点与风险（不改模型、不引新库）

1. **滚动控制器**：sticky 舞台容器（约 1000vh）；`progress = (scrollY − top) / (height − vh)`；
   rAF 阻尼平滑（沿用首页 hero 视差与 3D 现有 lerp 套路）。
2. **镜头关键帧**：现状只有 2 个固定机位；需扩为 N 个关键帧（幕 0–4 各机位 + 穿门段），
   按 progress 分段缓动；three 自带曲线插值可用。
3. **穿门方案二选一**（技术未知项，需先验）：
   - A. **暗场掩护机位切换**（推荐）：推近 → 暗 → 内景，零模型改动；
   - B. 检查门洞几何是否可真实穿越（可能要给模型开洞/做门动画，成本高）。
4. **灯光弧线**：`libraryLights` 参数化（天光 → 暗场 → 室内暖光），progress 驱动 lerp；
   reduced-motion 时直接定格。
5. **性能**（最大风险）：实时 WebGL（现状抗锯齿 + 软阴影）在滚动联动下必须守住演示机 60fps——
   **先做纵切片（幕 0–2）实测**再全量投入；护栏：canvas 仅在舞台内渲染（IntersectionObserver 停帧）、
   DPR 上限、阴影降级档。备选：预渲染序列帧（苹果老做法，会丢拾取交互，只作兜底）。
6. **滚轮冲突**：现在画布滚轮=缩放（`libraryRuntime.ts` wheel handler），必须让位给页面滚动。
7. **不引新依赖**：GSAP 维持移除状态；动效工具（useReveal / useScrollProgress / sticky 类）自建。
8. **动效层顺带清理**：design-audit 遗留（34 处 hover 无过渡、3 处焦点框缺失）在铺动效时一并清。

## 八、降级与可达（硬要求）

- 无 WebGL / 动效关 / prefers-reduced-motion：舞台替换为**每幕一张静态关键帧图**（提前截好），
  章节照常可读可跳，翻书保留——本页始终「文档可用」。
- 全部动效走 transform/opacity；键盘可达；无 CDN、离线自足（构建产物纪律不变）。
