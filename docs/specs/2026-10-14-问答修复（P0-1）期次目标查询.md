## 问题

问句点名某一期（「202603 那一期」「查5月的」）时，问答层三道缺口：

1. **规则规划器不解析问句期次**（消融原话：需「问句期次 → at/delta 规格」）；
2. 规划回落到 `series/all`（46 期全表），**模型自己在大表里对「5月」**——对不上就答「查不到」
   （真实数字、错误结论；T4/T5 实机复现）；
3. 证据与任务里**没有「问题指向哪一期」的明示**，写手靠猜。

## 方案（四件，最小改动）

1. **问句期次解析（唯一口径）**：`_qa.build` 复用 `_dialog.parse`（`today` 可注入）取期次——
   与对话前门同一套口径，不新增第二个解析器。
2. **规则规划**：问句点名期次、且问到了学科＋指标 → 出 **`at` 单值规格**（该期），不再铺 `series/recent`；
   没点名 → 现状逐字不变。
3. **模型规划面**：op 白名单加 `at`；prompt 指引「点名某期 → at；走势/多期变化 → series」；
   **期次由系统补**（模型面零数字不变——模型不写期次，执行器用本轮期次填充）。
4. **明示与证据**：任务首行加「本次问题指向期次 X（已解析）」；`_evidence` 增 `at` 渲染器
   （单值段＋到格 cells，与 series 同款来源链直出）。

## 边界

- 不动数据路径与红线；不改 dialog / 内核；**问句没点名期次的现状逐字不变**（既有测试钉住）；
- 「比上期呢」类多轮对比口径（M3）不在本票；qa 不做整轮换基期（产物基期仍由服务器路由决定）。

## 测试决策

- 规划单测：点名期次 → `at`（带期次）；未点名 → `series`（逐字不变）；模型面 `at` 归一（不带期次）；
- 证据单测：`at` 渲染文本 ＋ 到格 cells；
- qa 集成（`_seed_ledger`）：问「202605 那一期的化学接近度」→ 618.42 ＋ `台账#接近度/化学/202605`；
- 真机复放 rick T4/T5（「查5月的」）→ 答 202605 / 618.42，不再「查不到」。
