# 决赛演示态说真话（2026-10-20）

> 来源：2026-10-20 决赛产品审计（工作台 / 取数 / 预测 / 核验 / 灵活报告 / 对话 / 陈列馆 / 运行档案 / 逐格溯源）。
> 本 spec 只收「演示态说真话」这一刀；黄金动线、Agent 故事版、管理驾驶舱另立 spec。

## Problem Statement

决赛演示账号打开「问文衡」，本期任务显示 **202611**——一个只有取数状态文件、没有台账数据、也没有产物的未来期次；「取数」还被标成「进行中」。实际 **202609** 已出稿、签发失效，真正该做的是复核并重签。

评委看到的是：系统不知道自己在哪一期，也不知道哪一步真的在跑。这比任何功能缺失都更像「没做完」。

## Solution

本期任务先看「**有内容**」的期次（台账有效期次 ∪ 出过稿的产物目录）；只有本期三步全成且已签发，才顺延到下一期。只有取数状态文件、没有数据/产物的期次，不能抢占本期。

当前卡点仍用「●」标出，但话术从「进行中」改为「**待办**」；水位卡空态不再让已出稿的期次「先完成一次生成」。

## User Stories

1. 作为评委，我打开问文衡，看到的是当前报告期次 **202609**，而不是一个未来期次。
2. 作为馆员，我看到 202609 三步都完成、卡在签单，知道下一步是复核并重签。
3. 作为馆员，当本期确实已签发时，我看到下一期 **202611**，知道该等发布/取数。
4. 作为评委，我不会把「待办」误读成「正在下载」。
5. 作为演示者，我不需要解释为什么一个没跑的任务显示「进行中」。

## Implementation Decisions

- `taskview.scan` 的期次选择：`content = filled ∪ product_dirs ∪ acquired`；`known = content ∪ acquisition ∪ out_dirs`；`period = max(content)`，content 为空时才退回 `max(known)`。
- 出过稿（`generate_ok`）时，取数/并入两步按产物视为完成；`n_missing` 仍如实返回，前端说「已并入（缺 N 件）」，不把缺件说成「数据齐」。
- 顺延规则不变：只有 `acquire / merge / generate` 全成且 `status == signed` 才 `next_period`。
- `taskview.ts` 增加 `markLabel` 纯函数：`✓ → 已完成`、`● → 待办`、`○ → 未开始`；`DialogPage` 用它，不再硬编码「进行中」。
- 水位卡空态文案改为「本期看板还没生成」，不再指示已出稿的期次「先完成一次生成」。
- 不改 API、不改台账、不改 `out/`、不改权限。

## Testing Decisions

- 后端纯函数 `taskview.scan`：新增「202609 stale + 202611 只有取数状态」回归；新增「只有取数在途、没有内容」仍看新期。
- 前端纯函数 `taskview.markLabel`：三态文案直测。
- 不新增浏览器测试；现有 e2e 不覆盖此分支，且 e2e 会污染演示期，另票处理。

## Out of Scope

- 取数进程活性检测（真正的「正在下载」状态）。
- 评委只读证据面（trace / archive / red / ledger）。
- e2e 与演示期隔离。
- 黄金动线、Agent 故事版、管理驾驶舱。

## Further Notes

- 202609 当前 approval 为 `stale`（14:14 重出后未重签）；202611 只有 `opened` 状态文件。这不是数据错误，是期次选择逻辑把「在途」当成了「本期」。
- 该修复只读、零副作用；演示期数据保持真实状态。
