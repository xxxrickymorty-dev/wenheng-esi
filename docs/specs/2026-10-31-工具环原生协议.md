# spec：工具环升级原生多轮协议（追问死循环根治）

- **状态**：设计定稿（2026-10-31，rick 口谕「按 OpenAI 官方 function calling 循环改；复杂改动先出文档再落码」）。票 01–03 待落码。
- **关系**：《2026-10-28-问文衡接入fc》**续篇**——该篇把工具环做成「每轮全新单发会话」，实测暴露死循环；本篇把环升级为原生多轮协议。工具面白名单、执行器、编号续接、留痕两头、界面 ReceiptBar **全部不动**。
- **红线落点**：不变——模型只**选**（工具名+参数）不**造**；值只从引擎一条缝进来；出网零数字由构造保证；每次能力调用一条留痕。

## 病例与根因（2026-10-31 实测，留痕 `out/202609/ai_calls.jsonl`）

- 病例：追问「查最新的」（问句不含学科名 → 证据无学科段）→ 模型调 `query_at(阈值·物理学)`（**正确**，工具也查到）→ 结果以占位面折进下一轮「参考数据」→ 模型认不出这是自己调用的结果，**同参重复调用至步数上限** → `calls_unsupported` 回落（三次执行 5ms/1ms/1ms，后两次是执行器 memo 命中）。同日 15:40 **直问**（含学科名「物理学的 1% 阈值」）一次成功、零工具调用。规律：**直问不死，必须走工具环的追问必死循环**。
- 根因：`OpenAIBrain.think` 每次 payload 只有 `system + user` 两条消息——上一轮 assistant 的 `tool_calls` 与 `role:"tool"` 结果**从不进上下文**；工具结果被折进下一轮 `Brief.evidence`，与普通参考数据同形，模型无法把它绑定到自己的调用；temperature 0.2 下近似确定性重复。环内没有任何反馈打破僵局（无重复检测、末轮仍开放工具）。

## 契约（三票）

### 票 01 端口（`_brain.py`）

- `Brief` 增 `history: tuple = ()`：**协议形状**的既有轮消息（assistant `tool_calls` 消息 + `role:"tool"` 消息的 dict）；`egress_texts()` 在 history 非空时增 history 序列化一项（计入外发预算）。
- `Turn.calls` 每项增 `"id"`：取响应 `tool_calls[].id`，缺省合成 `call_<序号>`。
- `OpenAIBrain.think`：`messages = [system, user(_user_content(brief))] + list(brief.history)`；history 里 `arguments` 是 **JSON 字符串**（线上格式）。history 为空时 payload 与现状逐字一致。
- `_decode_call` 捕 id；`RuleBrain` 原样忽略 history/tools（规则部署物理上无工具环）。

### 票 02 边界环（`_attempt.py`）

- 工具结果**不再折进 evidence**：每轮执行后向 history 追加
  `{"role":"assistant","content":None,"tool_calls":[{"id":…,"type":"function","function":{"name":…,"arguments":"<JSON串>"}}]}`，
  再对每个调用追加 `{"role":"tool","tool_call_id":<同一id>,"content":<占位面结果>}`；
  下一轮 `Brief.evidence` 恒为**首轮证据**（结果只住在工具消息里，不重复发）。
- 执行前守卫逐字不变：执行器异常 → 回落；结果非占位面（strip_marks 后有裸数字）→ `GUARD_REJECT`；receipt/trace 只对**真实执行**收集。
- **末轮物理收口**：`step_now == steps` 那轮 `Brief.tools = ()`（等价 `tool_choice:"none"` 且兼容一切 OpenAI 兼容网关）；该轮仍回 calls → `CALLS_UNSUPPORTED`（reason 与 notice 文案不变，降为最后防线）。
- egress：bytes＝逐轮 `Brief.egress_bytes()` 求和（history 计入外发面）；items 明细按新外发面重算——**无工具路径的 items/bytes 断言逐字不变**，工具环用例的断言随新口径更新。
- 无 tools 路径（`tool_loop=False`）**逐字不变**（既有全例钉着）。

### 票 03 重复调用打断＋提示语（`_attempt.py` + `_core.py`）

- 边界按 `(工具名, 参数规范 JSON 串)` 去重：与本次 attempt 内任何已执行调用相同者**不再执行**，直接回一条 `role:"tool"` 消息：「（该查询已执行过，参数完全相同；结果见上面的同名工具消息。请依据已有结果作答，不要再调用工具。）」（构造上零数字）；不发 receipt、不发 trace。
- `QA_SYSTEM_PROMPT` 工具段增一句（零数字）：工具结果以工具消息回传——那是你刚才调用的返回值，读到即用、直接作答；同一个查询不要重复调用。
- `_qa._qa_executor` 的 memo 保留（同参取回同一段文本），与边界去重叠加无害。

## 兼容与风险

- 网关须认 `role:"tool"` 多轮（OpenAI 官方 / DeepSeek / MiniMax 兼容协议均支持）；个别网关不认 → HTTP 4xx → `BrainError(http_4xx)` → 既有回落语义，**不新增回落路径**。
- 推理模型把思考写进 content 只影响 text 路径（`_strip_think` 已有）；工具路径不受影响。
- history 里工具内容是**已过守卫的占位面**；assistant 侧只有工具名与参数枚举（无数字）——出网零数字不破。

## 测试（先红后绿；缝＝attempt + think + build）

- 边界：发工具 → 执行 → 第二轮 `brief.history` 含 assistant(tool_calls)+tool 消息且 id 配对、第二轮 evidence 不含结果文本；第二轮作答成功路径 receipts 照收；执行器异常 / `GUARD_REJECT` / 末轮仍 calls（断言末轮 `Brief.tools == ()`）→ 各回落码与文案不变；**重复同参调用第二次不触发执行器**、tool 消息为去重句；id 缺省合成；mapping 续号用例改写后仍绿；无 tools 全部既有用例逐字不动。
- 适配器：history 非空时 `payload.messages` 形状（tool_call_id 配对、arguments 为 JSON 串、user 消息不含结果文本）；`_decode_call` 捕 id / 缺省合成；坏 arguments JSON → `bad_response` 不变。
- qa：工具环用例改到 history 断言；同参重复第二次 `queries.execute` 不再被调。
- 红队：去重句本身无裸数字（能过 GUARD）。
- 全量：`uv run python -m pytest -m ""` 全绿；`uv run ruff check .` 干净；文档计数若 `tools/doc_counts.py` 报漂移按 `--write` 回写（本文档不手写用例数）。
