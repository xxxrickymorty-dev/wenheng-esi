# 老站下线清单（阶段 2 · 交后端执行）

> 背景：rick 拍板「新旧界面合并成一套，去掉重复的功能界面」。阶段 0（视觉统一）与阶段 1（功能迁移）已完成，
> 新工作区系统 `/app/` 已承接老站全部**日常**功能。本清单是**阶段 2：老站页面逐个下线**的执行依据。
>
> **执行方**：`server/` 与 `tests/` 属后端会话领地（见 `前后端分工与接口契约（2026-09-23）.md`），
> 本清单由前端会话整理，后端照单执行。前端不直接改这些文件。
>
> **纪律**：一次只下线一个页面；每下线一个，跑一遍 `server/e2e_check.py` 与
> `python -m pytest -m ""`，绿了再下一个。任何一步可停、可回退（老站页面在下线前一直可用）。

## 一、下线前的判据（逐条核对，全绿才动第一个页面）

| # | 判据 | 怎么验 |
|---|---|---|
| 1 | 新站里**没有任何链接**指向老站页面 | `Select-String -Path web\src\*.tsx -Pattern 'href="/p/\|href="/"\|/charts'` → 应为空 |
| 2 | 老站每个页面的功能，新站都有等价入口 | 见下表「新站等价入口」列，逐项点开确认 |
| 3 | 新站 e2e 全绿 | 前端会话的 `web/tools/` 与 playwright 脚本（生成台/报告/审核台/台账/分析台/对勘本/红件/图册/溯源） |
| 4 | 老站 e2e 仍全绿（下线前基线） | `python server\e2e_check.py` |

## 二、重定向映射表（老 URL → 新 URL）

**做法**：老路由改为 `RedirectResponse(新地址, status_code=302)`，**不要直接删路由**——
外部收藏、演示 PPT 里的旧链接、以及我们自己的历史文档都指着老地址，302 让它们都还能用。

| 老地址 | 新地址 | 说明 |
|---|---|---|
| `/`（首屏 = 对勘本/工作台） | `/app/` | 生成台（第一屏回答「我现在该做什么」） |
| `/run`（控制台） | `/app/` | 生成台（含上传台账/二维码/产物/重跑） |
| `/p/{期次}`（对勘本） | `/app/?view=reading&period={期次}` | 正文级阅读；`&section=` 可直达分组 |
| `/p/{期次}/redslots`（红件清单） | `/app/?view=red&period={期次}` | 全量清单 + 搜索 |
| `/p/{期次}/charts`（图册） | `/app/?view=charts&period={期次}` | 全量 + 搜索 + 按学科分组 |
| `/p/{期次}/trace`（逐格溯源） | `/app/?view=trace&period={期次}` | 分类 + 分页 |
| `/jobs/{任务号}`（任务页） | `/app/` | 生成台的 LiveRun 显示进度；产物/重跑在工具卡 |
| `/jobs/{任务号}/collation` | `/app/?view=reading&period={该任务的期次}` | |
| `/jobs/{任务号}/redslots` | `/app/?view=red&period={该任务的期次}` | |
| `/jobs/{任务号}/charts` | `/app/?view=charts&period={该任务的期次}` | |
| `/p/{期次}/archive`（运行档案） | ⚠️ **P2 未迁** → 暂不重定向，保留原页 | 见 §五 |
| `/p/{期次}/flexible`（灵活报告） | ⚠️ **P2 未迁** → 暂不重定向，保留原页 | 见 §五 |
| `/forecast`（预测） | ⚠️ **P2 未迁** → 暂不重定向，保留原页 | 见 §五 |

> 期次目录名可能带后缀（如 `202605_复现`）：重定向时用**原样字符串**（`urllib.parse.quote`），别做归一化。

## 三、要删的模板与静态资源

**下线一个页面 = 删它独有的模板 + 脚本 + 样式块**（样式块在 `style.css`/`collation.css` 里，按类名前缀切）。

| 页面 | 删 | 备注 |
|---|---|---|
| `/` `/run` `/jobs/*` | `templates/index.html`、`templates/job.html`、`static/index.js`、`static/job.js` | 三个入口共用同一批脚本 |
| `/p/{期次}` | `templates/collation.html`、`static/collation.css`、`static/collation.js` | `.whc-*` 类名是它独有的，可整段删 |
| `/p/{期次}/redslots` | `templates/redslots.html`（若有独立模板） | |
| `/p/{期次}/charts` | `templates/charts.html`（若有） | |
| `/p/{期次}/trace` | `templates/trace.html` | ⚠️ 等 P2 溯源迁完再删 |

**先查引用再删**：`Select-String -Path server\templates\*.html -Pattern 'include|extends'` 确认没有别的页面继承它们。

## 四、要改的测试与断言（**最容易漏，逐条对**）

| 文件 | 改什么 | 为什么 |
|---|---|---|
| `tests/test_stack_contract.py` | ① 老站路由**精确集合**断言（现有 20+ 路由）→ 收缩为「保留下来的那些」<br>② 9 条表单 POST 的精确集合 → 删掉随页面一起下线的那些<br>③ `/{` 与 `/run` 必须存在 → 改为 302 目标存在性断言 | 它钉的是「老站结构不变」，下线必然要改；**改的时候把新契约（302 映射表）也钉进去**，防止以后有人手滑删了重定向 |
| `server/e2e_check.py` | 逐页断言里删掉已下线的页面；**改为断言 302 落点**（如 `/p/202607` → 302 → `/app/?view=reading&period=202607`） | 部署验收脚本必须跟着走 |
| `tests/` 里其它提到老页面的用例 | `Select-String -Path tests\*.py -Pattern '/p/|/run|collation\.html'` 全查一遍 | 漏一个就是红的 |

> **建议**：把「302 映射表」做成 `server/config.py` 里的一个 dict（单一事实源），
> 路由与测试都读它——以后加/改映射只改一处。

## 五、P2 未迁的三项（**下线前必须先迁，否则不要重定向**）

| 页面 | 为什么还不能下线 |
|---|---|
| `/p/{期次}/archive`（运行档案） | 新站没有；技术复盘还要用（状态机回放/瀑布/审计结论/日志包）。需要后端先给 JSON（如 `GET /api/periods/{p}/archive`） |
| `/p/{期次}/flexible`（灵活报告） | 第二条产线，新站分析台不是它（分析台消费 `/api/analyze`，产的是解读；灵活报告是另一套产物）。需要先确认口径再迁 |
| `/forecast`（预测） | 新站没有；接口现成（`/api/forecast/run`），只差一个页面 |

**处理办法**：这三个页面**先保留原样**（它们仍在新站导航之外，靠直链访问），
等 P2 迁完再进本清单第二轮。**不要**为了「一次清干净」而重定向到新站一个不存在的等价页。

## 六、必须保留的（不随页面下线）

| 保留项 | 理由 |
|---|---|
| `/api/*` 全部 | 新站全靠它 |
| `/download/*`、`/chart/*`、`/qr.png` | 产物下载与图片：新站直接引用这些地址（`a.pill` 的 href、图册 `<img>`、工具卡二维码） |
| `/login`、`/logout` | 会话入口（新站没有自己的登录页——rick 定的：登录页只圆角化，不迁） |
| `/healthz` | 探活 |
| `collation-demo.html`（离线快照） | **离线演示件**：断网/评审现场的兜底，与服务器无关 |
| `/static/style.css` 的 `:root` 令牌 | 新站与老站同源令牌；老页面删了但令牌文件保留（`collation.css` 已删则无碍） |

## 七、ADR-0002 草稿（推翻 ADR-0001 的「旧站不改不迁」）

> 复制到 `docs/adr/0002-新旧界面合并.md`，按 ADR-0001 的格式写；要点如下。

**决定**：老站页面**逐个下线并 302 到新工作区系统**；老站只保留基础设施（`/api/*`、下载、图片、登录、探活、离线快照）。

**为什么推翻 ADR-0001**（原文：「旧站不改不迁」「旧站是唯一不能坏的东西」「否掉一次性重写旧站」）：
1. 两套界面并存造成**风格与入口分裂**（方的 vs 圆的；点「打开报告」被送去老站）；
2. 阶段 0/1 已把日常功能全部迁完并逐项验证，**重复的功能界面**成了负担而不是保险；
3. 演示与评审只剩一套入口，讲解与维护成本都降一半。

**代价（知情接受，rick 2026-09-23 已确认）**：
- **失去「不依赖 JS 也能签发/填写」**：真正无 JS 的写路径只有老站工作台与溯源页的表单；下线后写操作全依赖 JS。兜底只剩 `collation-demo.html` 快照（只读）；
- 老站 e2e 与栈契约测试要同步改（本清单 §四），**测试覆盖在迁移期会有一次空窗**——所以要求「一次只下线一个页面 + 每步跑全量测试」。

**回滚**：每个页面下线的提交都是独立的；回滚 = revert 那一个提交（路由与模板同时回来）。
**另**：下线前两仓各打一次 bundle（仓库① 无远程，这是它唯一的异地备份）。

## 八、执行顺序（建议）

1. 核对 §一 四条判据 → 全绿
2. 先做 §五 的 P2 迁移（或明确「本轮不下线这三页」）
3. 建 302 映射 dict（单一事实源）+ 改测试（此时**还没删页面**，测试应全绿）
4. 逐个页面：改路由为 302 → 跑 `e2e_check.py` + `pytest` → 绿了再删模板/静态 → 再跑一遍 → 提交
5. 全绿后：写 ADR-0002 → 打 bundle → 通知前端会话做一次全站走查（新站里不再有任何指向老站的链接）
